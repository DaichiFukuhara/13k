## 1. これは何か（実装されている作品定義）

**シードから技構成だけを生成した未知のボス3体と、横1画面で連続して戦う2Dアクション。**

- 1ラン = **ボス3体**（`tier` 0 / 1 / 2）。最後の1体が最終ボス
- **1体倒すごとにプレイヤーは全回復**（`startBoss()` が `p` を作り直す）
- 難易度は**敵側だけ**で上がる（`tier` が危険度帯域・HP・体勢を上げる）。プレイヤーは成長しない
- 敗北時は**同じボスへ即再挑戦**でき、技・数値・外見は変わらない
- 16:9 固定・**640×360** の内部解像度。スクロールしない。床は平面

> 🧭 根の 1.8（ランの構造・仮置き）は「ボス何体か」を下位へ送っていたが、
> **実装は既に3体で答えを出している。**

## 2. 生成するもの / 生成しないもの

根の 1.2 の境界は、**実装でもほぼそのまま成立している。**

| | 実装での中身 |
| --- | --- |
| **生成する** | 攻撃技4〜5個（形状・数値・修飾子）/ 防御能力0〜1個 / 外見（主色・武器シルエット）/ 技の山札の並び / 最終ボスの第2形態変異1個 |
| **生成しない** | 当たり判定の形状（`moveRect()` の6種固定）/ 予備動作開始後の発生時刻 / 攻撃開始後の標的位置 / 攻撃後硬直 / パリィ可能性 / プレイヤーの基本性能 / リトライ時の技セット |

**乱数の分離が実装されている。**ボス生成は `seeded()`（Mulberry32）の系列だけを使い、
火花・画面揺れの `Math.random()` とは別系統。
**見た目の乱数を何回呼んでも次のリトライのボス構成は変わらない**（不変条件9 の実効化）。

## 3. 技（Move）— 9要素の配列

容量のためオブジェクトではなく配列。**これが「技」の実体である。**

| 添字 | 名前 | 値域 | 実フレーム / ピクセルへの変換表 |
| --- | --- | --- | --- |
| 0 `S` | 形状 | 0〜5 | SWEEP / THRUST / SLAM / CHARGE / SHOT / RAIN |
| 1 `D` | 威力 | 1〜4 | プレイヤー HP から直接引く |
| 2 `R` | 射程 | 1〜4 | `REACH = [48, 82, 136, 250]` px |
| 3 `W` | 予備動作 | 1〜4 | `WIND = [24, 36, 54, 80]` F |
| 4 `A` | 攻撃判定の持続 | 1〜3 | `ACTIVE = [5, 8, 12]` F |
| 5 `C` | 攻撃後硬直 | 1〜4 | `REC = [18, 32, 50, 76]` F |
| 6 `T` | 追尾 | 0〜2 | 予備動作中の標的更新と、弾の曲がり |
| 7 `N` | 多段 | 1〜3 | 同じ攻撃の段数 |
| 8 `F` | **宣言** | ビット和 | `PARRY=1` / `JUMPABLE=2` / `MOVEABLE=4` |

**`m[F]` が、根の共通語彙でいう「宣言」（どの回答手段で抜けられるか）そのものである。**

### 形状6種と当たり判定（`moveRect()`）

**表示と判定は同じ関数を通る。**これが不変条件8（予告と当たり判定は同一定義）の実効化。

| 形状 | 当たり判定 | 宣言される回答 |
| --- | --- | --- |
| 0 SWEEP | 床上 24px の横長矩形（`reach` × 24） | 移動 / **ジャンプ** / パリィ |
| 1 THRUST | 胸元から正面へ伸びる細い矩形（`reach` × 18） | 移動 / パリィ |
| 2 SLAM | ボス中心の地上矩形（`reach+44` × 57） | 移動 |
| 3 CHARGE | 移動中のボス本体（37 × 68） | 移動 / **ジャンプ** / パリィ |
| 4 SHOT | 矩形なし。`shots` 配列の弾で処理 | 移動（弾はパリィで**反射**できる） |
| 5 RAIN | 生成時に固定した X への縦矩形（`28+R*9` × 289） | 移動 |

- **床付近（SWEEP）だけがジャンプで越えられる。**根の 1.7 の「床付近か高さありか」に対応
- RAIN の標的 X は `startMove()` で確定し、**攻撃開始後は動かない**（不変条件7）
- 追尾（`T>0`）は**予備動作の前半 62% までしか標的を更新しない**

## 4. 危険度と、その抑え方

### 危険度（`threat()`）

```
threat = DMG_COST[威力] + RANGE_COST[射程] + WIND_COST[予備動作] + REC_COST[硬直]
       + 追尾×2 + (多段−1)×2 + (持続が最大なら +2)
```

| 表 | 値 | 意味 |
| --- | --- | --- |
| `DMG_COST` | 威力1〜4 → **1 / 3 / 6 / 9** | 線形でない。高威力を重く扱う |
| `RANGE_COST` | 射程1〜4 → 0 / 1 / 3 / 5 | |
| `WIND_COST` | 予備動作1〜4 → **+4 / +2 / 0 / −2** | 短いほど加点、長いほど**減点** |
| `REC_COST` | 硬直1〜4 → 0 / −1 / −3 / −5 | 長いほど減点 |

**根の 1.3「特性と代償は別の軸」が、加点と減点として実装されている。**
「短い予備動作の代償が長い予備動作」という矛盾は、実装には**最初から無い**
（同じ `m[W]` の1軸なので、両方を持てない）。

### 予算（`limits()`）

```
通常技  : [3+tier, 6+tier]
固有技  : [6+tier, 8+tier×2]
```

> ⚠️ **これは「ボス1体が持てる合計」ではなく「技1つが収まる帯域」である。**
> 根の共通語彙は 危険度予算 を「**ボス1体が持てる**危険度の範囲」と定義している。
> **定義がずれている**（§8 の差分5）。

### 禁止組み合わせ（`harden()`）

**予算とは別に、無条件で崩す。**`balance()` の反復中にも毎回呼ぶので、
数値調整で禁止構成へ戻れない。

| 条件 | 強制的にどうするか |
| --- | --- |
| 最速 24F | 威力 ≤2、追尾 ≤1、**単発のみ** |
| 威力4 かつ 全域射程 | 予備動作 ≥54F、硬直 ≥50F |
| 全域射程 かつ 強追尾 | 威力 ≤2、予備動作 ≥36F |
| 3段攻撃 | 1段の威力を **1 に固定** |
| 長時間持続 かつ 強追尾 | 追尾を 1 へ下げる |

### 帯域へ寄せる（`balance()`）

最大24回の単調補正。**強すぎる時は硬直 → 予備動作 → 追尾/多段/威力/射程の順に落とす。**
つまり**個性を消す前に、プレイヤーへ反撃時間を返す。**
24回で打ち切るので**無限ループしない**（根の「停止性」に対応する実装上の保証）。

## 5. セット単位の保証（`generateBoss()` の後処理と `validateBoss()`）

**技1つずつではなく、ボス1体の技セット全体に条件を課している。**ここが公平性の本体。

### 生成時に強制すること

| # | 内容 | 実装 |
| --- | --- | --- |
| 1 | 技の役割枠を先に決める | `[突き, 横薙ぎ, 接近/遠距離, 範囲制圧, 固有技]` |
| 2 | **GAP 枠が全域へ圧力をかける** | 3番目が突進でなければ射程を4へ上げる |
| 3 | **反撃機会を最低2つ** | 硬直 ≥50F の技が2つ未満なら、`open()` で強制的に延ばす |
| 4 | **高速技は1体に1つまで** | 2つ目以降の 24F 技は 36F へ落とす |
| 5 | 外見色は**生成結果の関数** | 実際に出た特性候補（高威力/長持続/高速/防御/長射程/追尾/多段）から選ぶ |

### 検査（`validateBoss()`）

**開発専用。**Terser が未使用関数として提出版から落とすので、ZIP には入らない。

| 検査 | 落ちる条件 |
| --- | --- |
| 技数 | 1体目4技 / 2・3体目5技でない |
| **ジャンプ回答** | `JUMPABLE` の技が**0個** |
| **パリィ回答** | `PARRY` の技が**2個未満** |
| 遠距離への圧力 | 射程4 も突進も無い |
| **反撃窓** | 硬直 ≥50F の技が**2個未満** |
| 高速技 | 24F 技が**2個以上** |
| 帯域 | `threat` が `limits` の外 |
| 個別の禁止 | `harden()` の5条件を通り抜けたもの |
| 数値健全性 | NaN / Infinity |

`test.mjs` が **10,000 シード × 3 tier = 30,000体**を生成し、
**(a) 同一シードの2回生成がバイト一致すること**と **(b) 検査エラー0件**を確認する。
2026-09-04 時点で **pass**（6形状・4防御・21種の外見が出現）。

> 🧭 **これが実装版の「公平性の保証」である。**
> 「安全席が存在する」ではなく「**セットの中に、ジャンプで抜ける技が1つ以上、
> パリィできる技が2つ以上、反撃できる技が2つ以上ある**」で保証している。
> 根の 1.3 とは**別の設計**である（§8 の差分3）。

## 7. ボスの行動（状態機械と山札）

```
wait ──► wind ──► active ──► recover ──► wait
 │                                        ▲
 ├─► guard   （SHIELD 持ちが山札一巡ごとに 60F 構える）
 ├─► stagger （体勢0で 110F の大きな隙）
 └─► shift   （最終ボス HP50% の 75F 変異演出）
```

- `wait` 中は距離を **105〜245 px** へ寄せる。**敵弾が画面に残っている間は待機を止める**
  （独立した攻撃の重なりを防ぐ）＝ 事実上の**同時予告上限**
- `recover` 中と `stagger` 中はプレイヤーの与ダメージ **1.25倍**。反撃窓が明示されている

### 山札（`nextMove()`）

1. 空なら全技をシャッフル。**シャッフルのシードは `ボスseed + 周回数×97`** なので、
   描画や入力の乱数に依存しない（決定論）
2. 一巡するまで同じ技を戻さない
3. **先頭3枚だけ**を見て、現在距離で届く最初の技を選ぶ

**3 が、根の「選択時の条件」に相当する唯一の実装である。**
ただし条件は「**届くか**」であって「プレイヤーが安全席に居るか」ではない。

### 防御能力（`b.defense`）

| 値 | 名前 | 効果 |
| --- | --- | --- |
| 0 | なし | 1体目は常にこれ |
| 1 | ARMOR | 通常時の体勢ダメージ半減 |
| 2 | BARRIER | 弾ダメージ 30%。**近接を当てると 180F 破壊** |
| 3 | SHIELD | 山札一巡ごとに 60F 構え、HP30% / 体勢35% しか通さない |

### 体勢

ボスの第2の耐久値（最大 24 / 32 / 42）。0 で **110F の stagger**。
パリィ成功で 8 削る。**根の共通語彙の「体勢」がそのまま実装されている。**
