## 1. 作ろうとしているゲーム

**js13kGames 2026 提出作品**（テーマ「Unicorns and Rainbows」）。

> シードから技構成だけを生成した未知の敵を観察し、
> 移動・ジャンプ・ローリング・パリィを使い分けて崩す、1画面固定の2Dボスアクション。

### 中心にある1つのアイデア

**生成するのは敵の「技構成」だけ。戦闘が始まったあとの判定は一切生成しない。**

| | 中身 |
| --- | --- |
| **生成する** | 攻撃技4〜5個（形状・数値・修飾子）／防御能力0〜1個／外見／技の山札／最終ボスの第2形態変異 |
| **生成しない** | 当たり判定の形状／発生時刻／標的位置／攻撃後硬直／パリィ可能性／プレイヤー性能／リトライ時の技セット |

だからプレイヤーが向き合うのは**乱数ではなく「未知だが固定された相手」**。
死ぬたびに別の正解を引くのではなく、**同じ相手を観察して学習する**。
これがソウルライクとして成立する条件そのものになっている。

### ルール

- **操作は1人**。手段は 移動 / ジャンプ / ローリング / パリィ の**4つだけ**
- **資源はスタミナ1本**。回避も攻撃も食う。消費後は回復が止まる。
  だから「回避し続ける」も「殴り続ける」もできない
- **すべての生成攻撃に、最低2種類の対処がある**
  - 反射神経を要求しない方法（早めの移動・距離を取る・ジャンプで越える）
  - 難しいが反撃しやすい方法（懐へロール・パリィ・近距離維持）
- **強い特性には必ず代償**（長い予備動作か長い攻撃後硬直）。
  理不尽な敵が出ることを、運ではなく**構造で防ぐ**
- **1画面固定・横軸1本**。スクロールなし、落下死なし、足場なし、奥行きなし

### 虹は装飾ではなくルール

7色が攻撃特性の語彙になっている。**ボスの主色は「最も危険度へ寄与した特性」から決まる**ので、
見た目が生成結果の関数になっている。

| 色 | 意味 | | 色 | 意味 |
| --- | --- | --- | --- | --- |
| 赤 | 高威力 | | 青 | 長射程 |
| 橙 | 長い攻撃判定・残留 | | 藍 | 追尾 |
| 黄 | 短い予備動作 | | 紫 | 多段・特殊変化 |
| 緑 | 防御能力 | | | |

ただし**色だけに依存させない**。範囲・時間・動きでも同じことを示す。

> これがテーマ条件の答えになっている。「色を取り除くと、敵の性格を推測する手段が
> 予備動作の観察だけになり、初見の判断が**推測から反応へ落ちる**」。
> 虹を外すとゲームが別物になる、という形でテーマがルールに接続している。

### 「完成した」の判定は2点だけ

機能数でも生成パターン数でもない。

1. **生成された攻撃が、初見では緊張し、一度見れば理解できる**（＝理不尽でないこと）
2. **同じ敵への再挑戦で、乱数ではなく学習によって勝率が上がる**（＝上達が起きること）

## 4. 2026-09-02 の見直しで見つかったこと

前検査3周は**すべて分割提案を対象**にしていた。`precheck.md` は分割提案への前検査しか
規定しておらず、**決定本文（1〜7）そのものは一度も体系的に検査されていない**。そこを読んだ。

### 🔴 A. 「交代」の消し残しが、もう1件あった

`1.8` に **「1体ごとに全員回復し」** と残っていた。操作キャラは1人なので「全員」はおかしい。

これは Codex が重大5として見つけた「本文1に『交代』が残っていた」と**まったく同じ型**で、
**同じ改訂（3人交代の削除）の消し残し**。3周の前検査すべてが見落とした。**修正済み。**

> **意味すること**: 改訂のたびに全節を突き合わせる工程が無い。
> 1箇所直して他を放置する型（`precheck.md` 確認項目7）が、**この木では2回起きている**。

### 🔴 B. 公平性の保証が、論理的に壊れた条項に乗っている

`1.3` はこう書かれている。

> 高威力・長射程・追尾・多段・**短い予備動作**といった強い特性には、
> 必ず**長い予備動作**か長い攻撃後硬直を対応させる

**「短い予備動作」の代償が「長い予備動作」になっている。**同じ攻撃が短い予備動作と
長い予備動作を同時に持つことはできないので、黄（＝短い予備動作）の代償は実質
「長い攻撃後硬直」1択しかない。**特性リストと代償リストが独立に書かれていて、
`短い予備動作` が両方に入っているのが原因。**

これは表現の粗さでは済まない。依存が積み上がっている。

```
不変条件10（反射神経に依存しない回答を最低1つ持つ）
   ↑ 依存
1.4（すべての生成攻撃は最低2種類の対処を持つ）
   ↑ 依存
1.3（強い特性には必ず代償）  ← ここが壊れている
```

**このゲームが「理不尽でない」ことの保証は、すべて 1.3 に乗っている。**

さらに 黄 は `s2.read-floor`（読むために必要な最低予備動作長・暫定18F）とも衝突する。
最低長で下から抑えると、**黄は「絶対的に短い」のではなく「他より短い」になる**。
初見のプレイヤーは他と比べる材料を持っていないので、**色を絶対値として読めない**。
受け入れ条件「初見」に直接効く。

### 🔴 C. 容量配分の単位が書かれていない

`13,312 bytes` は **ZIP のサイズ**（受け入れ条件「提出可能」）。一方、容量配分の表は
モジュールごとに「2.2〜2.8KB」のように割り当て、**合計 8.3〜11.2KB・自主ゲート 11.8KB** と
13,312 bytes の隣に並べている。

**この KB がソース由来なのか ZIP 由来なのかが、どこにも書かれていない。**

- ZIP バイトだとすると、**圧縮は全体で効くのでモジュール単位に按分できない**（配分が無意味）
- ソースバイトだとすると、**13,312 bytes と直接比べられない**（比較が無意味）

どちらに解釈しても表が壊れる。しかも**この数字はプロジェクトで最も影響が大きい制約**であり、
`duel` と `read` の両方の「継承する制約」に確定値として降りる予定になっている。

### 🟡 D. 「戦闘座標は横軸1本だけ」と「ジャンプで越える」

`1.7` は「戦闘座標は**横軸1本だけ**」「奥行きを持たない」とする。
一方 `1.4` は回答手段に **ジャンプ**を挙げ、「ジャンプで**越える**」と書く。

越えるには縦方向の座標が要る。1.7 が否定しているのは Z軸（奥行き）なので、
おそらく Y軸（高さ）は存在する意図だが、**「横軸1本だけ」という文はそう読めない**。
実装者が最初に止まる箇所。

### 🟡 E. 日数の直書きが古くなっていた

`3` と `7-1` が「残り13日」と書いていた（8/31 時点の数）。実際は 11日。
**この文書は残り日数を根拠に判断を下している箇所が複数ある**（6 のボス体数、
7-1 の完成範囲、7-5 の打ち切り）ので、古い日数は判断の前提を静かに崩す。
**締切日時を書く形へ修正済み。**
