# Codex 設計監査 — 2026-09-04

## 判定

**HOLD — 現在の正本のまま実装フローへ渡してはいけない。**

設計の骨格（`gen → fight → s1 → read`、`roster` / `arena` / `palette` をハブにする切り方）は
維持できる。全面的な作り直しは不要。ただし、2026-09-04 に追加した「凍結」内容が
有効版・子への振り分け・葉の本文へ一貫して反映されておらず、実装者が閉包だけを読んだ場合に
異なる実装へ到達する。さらに、停止性と公平性の証明に直接関わる未定義が残っている。

この監査でいう「次のフロー」は、設計ツリーを実装者へ渡して縦切り実装を始める工程を指す。

## 着手前に必ず直すこと（P0）

### 1. 有効な版と承認状態を一意にする

現在は、本文で新しい決定を凍結しながら、frontmatter と「現在有効なもの」が旧版を
`active` としている。

- `tree/index.md:6-18` は `decision-7` / `split-7` と `waiver-1` を現在値としている一方、
  `tree/index.md:2372-2382` は `decision-8` / `split-8` / `approval-1` を現在値としている。
- `tree/index.md:2709-2711` は `split-8` の成立後も `split-7` を `active` としている。
- `tree/index.md:2676-2678` は `s1` の変更が `duel` / `read` と全子孫を失効させると明記するが、
  失効先の版参照・承認証跡は更新されていない。
- 次のノードは本文中に `decision-2` または `decision-3` の凍結を持つが、有効版表は旧版のまま。
  `duel`、`gen`、`fight`、`read`、`frame`、`audit`、`foe`、`palette`、`hud`、`shell`。
  `tell` だけは `decision-2` / `split-2` へ更新済み。

**修正条件:** 各ノードで、frontmatter、現行本文、分割提案、子の `parent_decision_ref`、
「現在有効なもの」、承認証跡を同じ版へそろえる。旧版は `superseded` とする。
`s1`、seam、責任、受け入れ条件の変更を受けた部分木は、ハーネスの失効規則どおりに
新しい決定・分割版を切り、**どのファイル内容を人間が承認したか**を版参照で確定する。
包括承認の引用だけで、編集後の任意の版まで自動承認された扱いにはしない。

### 2. 凍結した新ルールと旧仮置きの二重記述を解消する

同一ノードの有効本文に、互いに両立しない命令が残っている。

- `audit` は `tree/duel/gen/audit/index.md:83-115` で時空間到達可能性を使うと凍結したが、
  `:250-253` では「無敵F ≥ 持続F」だけでタイミングを問わない旧仮置きを残している。
- `foe` は `tree/duel/fight/foe/index.md:66-102` で全長走査＋12F待機を凍結したが、
  `:273-278` では再シャッフルする旧仮置きを残している。
- `foe` は `:167-179` で第2形態を検査済み版へ切り替えるだけとしたが、`:260-271` は
  未解決・`provisional` のまま記述している。
- `arena` は `tree/duel/fight/arena/index.md:198-205` で「形状を展開するのは `arena` だけ」かつ
  第2形態は `foe` が書き換えるとしている。これは `tree/duel/index.md:781-803` の

  「関数呼び出しであって seam ではない」としている。親 `tell` の現行決定では `t1` / `t2` の
  seam である。

**修正条件:** 旧文を履歴として残すなら、現行の命令として読めない `superseded` 節へ移す。
「分からないこと」には、すでに凍結して解決した事項を未解決として残さない。

### 3. フォールバック技を実在する契約として定義する

`tree/duel/gen/roster/index.md:68` は「1.2.1 で具体値を凍結」と参照するが、同ファイルに
`1.2.1` は無く、9パラメータの固定値も無い。具体値は `design/README.md` の要約にしかなく、
要約は正本ではない。この状態では「必ず検査を通る固定フォールバック」による停止証明が成立しない。

**修正条件:** `roster` の現行本文へ、9パラメータ、特性、回答集合、安全席の要否、
第2形態での扱いを記載する。その固定値を新しい `audit B` に通す回帰試験を受け入れ条件へ追加する。
要約にある THRUST 案を採る場合も、実測で合格してから「必ず通る」とする。

### 4. 黄技選択の停止性を修正する

`tree/duel/fight/foe/index.md:95-102` の有限停止の説明は成立しない。セット全体に非黄があっても、
一巡の末尾で「未使用カードが不適格な黄1枚だけ」になることがある。プレイヤーが安全席へ
移動しなければ、同じ1枚を12Fごとに再走査し続け、戦闘が進まない。

**修正条件:** 不適格な黄を保留して次周回を開始する、山札全体を復元して適格な非黄を選ぶ、
または明示的な非攻撃行動へ移る、のいずれか1つを選ぶ。山札の公平性と連続使用条件を含め、
状態遷移が有限回で攻撃または別の進行状態へ到達することを示すテストを追加する。

### 5. 公平性検査に必要な SHOT の時空間仕様を埋める

`tree/duel/index.md:787-803` の展開規則は SHOT について速度と Y 追尾に触れるだけで、
発射位置、弾の当たり判定寸法、寿命、追尾更新式、段ごとの発射時刻を定義していない。
一方 `audit B` は全初期位置・全段・弾道を含む保守的到達可能性を要求する。
この入力不足では SHOT の有効回答集合を判定できない。

**修正条件:** `duel` の共通展開規則に SHOT の完全な時空間仕様を置き、`audit` と `arena` が
同じ純関数または同値な確定規則を使うと明記する。実装既存値を採るなら、その値を正本へ転記する。

### 6. seam の送受信を端から端まで一致させる

- `gen` の現行 `g1` / `g2` は `tree/duel/gen/index.md:230-233` で「乱数の値列」と

  `tree/duel/gen/move/index.md:37-38` で乱数関数を受け、技＋危険度だけを返す。
- 根の `s1` は `tree/index.md:2083-2095` で完全スナップショットを要求するが、
  `arena` の組み立て表 `tree/duel/fight/arena/index.md:114-125` は旧版のままで、座標、最大値、

**修正条件:** 各 seam について、送信者の出力、親の seam 表、受信者の入力、`s1` の組み立て表を
同じフィールド集合へそろえる。値を別の祖先定数から得るなら、出所を明示する。

### 7. 根の生成境界を現行の技表現へ合わせる

`tree/index.md:75-76` は攻撃後硬直とパリィ可能性を「生成しない」とするが、

**修正条件:** 「生成しない」を、戦闘開始後に変化させない値と、実行時に展開する値へ分ける。
少なくとも、技パラメータとして生成する硬直・宣言と、実行時の発生時刻・展開済み当たり判定を
同じ行へ混ぜない。

### 8. 被験者未確保時の縮退条件を根で決める

**修正条件:** 履歴を削除する必要はないが、各ノードの先頭から「現行決定本文 → 現行分割 →

## 再判定の合格条件

次の5点がすべて満たされたら、縦切り実装へ進める。

1. 全20ノードで有効な決定・分割・親参照が一意で、失効版が `active` ではない。
2. P0 の二重記述が無く、フォールバックと黄技選択に有限停止の根拠がある。
3. SHOT を含む全6形状を、同じ規則で `audit` と `arena` が扱える。
4. `g1`〜`g4`、`f1`〜`f4`、`d1`、`s1`、`t1` / `t2` の送受信フィールドが一致する。
5. 修正後の版に対して別実装 AI の前検査と人間の承認が記録され、実装者の入口が定義されている。

合格後の最初の実装単位は、既存の勧告どおり
**1シードの生成 → A/B/C 検査 → 1戦 → `s1` → 最小描画**の縦切りでよい。
