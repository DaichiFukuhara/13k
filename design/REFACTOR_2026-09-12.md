# 重複削減4案の個別検証（2026-09-12）

前段の不要コード除去後（ZIP 12,720 bytes）を共通の基準にした。
4案を別々のコピーへ適用し、ビルド・既存回帰テスト・変更前後の比較を行った。
これはゲーム仕様の追加承認ではなく、現在の動作を保った構造変更の検証記録。

## 容量と採否

同じTerser設定・deflate level 9・単一index.htmlのZIPで実測した。
各案の差分は独立した基準との比較であり、累積値ではない。

上限13,312 bytesに対する余裕は630 bytes（約4.7%）。
前段の不要コード除去前13,311 bytesから通算629 bytes削減した。
文字列・タイミング案はHTMLが短くなってもZIPが増えた。ソースの重複削減と
deflate後のサイズ削減は同じではない。この結果は今回試した実装についての値であり、
同じ目的を持つ別の書き方すべてが増量するという意味ではない。

## 各案で試した変更

### 1. 多角形描画

`drawPerson()`と`unicorn()`内の2つの`poly()`を共通関数へ移した。
頂点列・色・描画順・座標変換は維持する。共通関数ではパス作成後、fill直前に色を設定する。
元のユニコーン側はパス作成前に色を設定していたが、パス作成はfillStyleを参照しない。
比較テストは描画実行時のスタイルを照合するため、この代入順の差で誤検出しない。

### 2. Resultの技説明文字列

撃破ログと現在の所持技が使う「形状名・射程px・発生F・消費ST」のテンプレートを
`moveSummary(m)`へ集約した。文字・空白・座標・フォント・色は維持する。
Resultに実際の撃破ログと所持技を用意し、6形状×6進行段階で描画を比較した。
ZIPは2 bytes増えたため、現行コードには反映していない。

### 3. ボス照準更新

攻撃開始とwind中追尾に重複していたtarget・aimY・face・各段の落下X更新を
`aimBoss(m)`へ集約した。攻撃開始時だけ配列を作り直し、追尾中は既存配列を書き換える。
追尾条件`T > 0`かつ`残りwind > 全長×0.38`は維持する。
追尾0/1/2、端と中央、短長wind、1〜3段で境界前後を検査し、配列参照も保持されることを確認した。

### 4. 攻撃タイミング

`attackTiming(m,t,active)`を追加し、span・終端・段番号・判定有効中かを返す方式を試した。
`activeEnd`、プレイヤー攻撃、敵攻撃、予告、人型の敵姿勢、プレイヤー判定表示で利用した。
敵のACTIVE表とプレイヤーの`m.active`は分け、敵予告の`timer−1`も呼び出し側に残した。
発生前、発生、段間、次段開始、最終段終了、硬直終了で比較した。
ZIPは53 bytes増えたため、現行コードには反映していない。
実行速度・オブジェクト割り当ての負荷は計測していない。

## 実行した検査

4案それぞれ、および採用2案を合わせた現行コードで以下を完走した。

- `test.mjs`: 90,000ボスの生成・再現性・制約。
- `steal.test.mjs`: 28,000技の変換と全形状の連続使用。
- `experience.test.mjs`: 試用、確定、リトライ、エンドレス、ポーズ、被弾・反撃など12件。
- `telegraph.test.mjs`: 82条件の予告・段間・範囲と描画の状態非変更。
- `roles.test.mjs`: 技の役割、多段効果、移動、角・胴体、虹、描画など13件。
- `opportunities.test.mjs`: 反撃機会・バリア・18条件の空振り/硬直。
- `audio.test.mjs`: 実イベントの命中音・パリィ・体勢・撃破・獲得・音声API不在。

追加した`prismatic-duel/refactor.test.mjs`で、各案を保存した基準ソースと比較した。

| 比較内容 | 各案の条件数 |
| --- | ---: |
| ボスの形状・段数・向き・状態・時刻の描画 | 3,024 |
| プレイヤー攻撃の発生・段間・終端の描画 | 432 |
| 照準の初期化と追尾境界の状態 | 540（初期化照合は別途） |
| Resultの技説明・進行 | 36 |
| 上記合計 | 4,032 |
| キーボード/RAF経由の基準・変更後・実ビルド比較 | 4シード×900 = 3,600フレーム |

比較対象はCanvas描画命令、描画時のスタイル、Canvas save/restoreの釣り合い、
変更前後の戦闘状態、localStorageの値、操作説明。描画による状態変更も検査する。
実ブラウザでのピクセル比較や人によるプレイ評価ではなく、Node VM上の比較である。
検査範囲内で差異は検出されなかった。

最終コードでは`submit.mjs`も完走し、2回ビルドのZIP一致、単一の最上位index.html、
展開結果一致、外部参照なし、容量上限を確認した。アップロード・コミット・pushは行っていない。
