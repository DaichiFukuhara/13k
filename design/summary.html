ゲームの中身

この企画の中心は、生成する / しないの境界そのものにある。

生成するのは敵の「技構成」だけ。戦闘が始まったあとの判定は一切生成しない。

区分中身
生成する攻撃技4〜5個（形状・数値・修飾子）／防御能力0〜1個／外見／技の山札／最終ボスの第2形態変異
生成しない当たり判定の形状／発生時刻／標的位置／攻撃後硬直／パリィ可能性／プレイヤー性能／リトライ時の技セット

だからプレイヤーが向き合うのは乱数ではなく、未知だが固定された相手。死ぬたびに別の正解を引くのではなく、同じ相手を観察して学習する。ソウルライクとして成立する条件そのものが、この一線に乗っている。

ルール

  • 操作は1人。手段は 移動 / ジャンプ / ローリング / パリィ の4つだけ
  • 資源はスタミナ1本。回避も攻撃も食い、消費後は回復が止まる。「回避し続ける」も「殴り続ける」もできない
  • すべての生成攻撃に、最低2種類の対処がある。反射神経を要求しない方法（早めの移動・距離を取る・ジャンプで越える）と、難しいが反撃しやすい方法（懐へロール・パリィ・近距離維持）
  • 強い特性には必ず代償。理不尽な敵が出ることを、運ではなく構造で防ぐ
  • 1画面固定・横軸1本。スクロールなし、落下死なし、足場なし、奥行きなし

虹は装飾ではなくルール

7色が攻撃特性の語彙になっている。ボスの主色は「最も危険度へ寄与した特性」から決まるので、見た目が生成結果の関数になっている。

赤高威力
橙長い攻撃判定・残留
黄短い予備動作
緑防御能力
青長射程
藍追尾
紫多段・特殊変化

ただし色だけに依存させない。範囲・時間・動きでも同じことを示す。これがテーマ条件の答えにもなっている。

色を取り除くと、敵の性格を推測する手段が予備動作の観察だけになり、初見の判断が推測から反応へ落ちる。虹を外すとゲームが別物になる。

「完成した」の判定は2点だけ

機能数でも生成パターン数でもない。

  • 生成された攻撃が、初見では緊張し、一度見れば理解できる（＝理不尽でないこと）
  • 同じ敵への再挑戦で、乱数ではなく学習によって勝率が上がる（＝上達が起きること）

見直しで見つかったこと

前検査3周はすべて分割提案が対象だった。決定本文（1〜7）そのものは一度も体系的に検査されていない。そこを読んだ。

重大修正済み A 「交代」の消し残しが、もう1件あった

1.8 に「1体ごとに全員回復し」と残っていた。操作キャラは1人なので「全員」はおかしい。

これは Codex が重大5として見つけた「本文1に『交代』が残っていた」とまったく同じ型で、同じ改訂の消し残し。3周の前検査すべてが見落とした。改訂のたびに全節を突き合わせる工程が無く、1箇所直して他を放置する型がこの木では2回起きている。

重大 B 公平性の保証が、論理的に壊れた条項に乗っている
高威力・長射程・追尾・多段・短い予備動作といった強い特性には、必ず長い予備動作か長い攻撃後硬直を対応させる

「短い予備動作」の代償が「長い予備動作」になっている。同じ攻撃が両方を持つことはできないので、黄（＝短い予備動作）の代償は実質「長い攻撃後硬直」1択しかない。特性リストと代償リストが独立に書かれ、短い予備動作 が両方に入っているのが原因。

表現の粗さでは済まない。依存が積み上がっている。

不変条件10（反射神経に依存しない回答を最低1つ持つ）
   ↑ 依存
1.4（すべての生成攻撃は最低2種類の対処を持つ）
   ↑ 依存
1.3（強い特性には必ず代償）← ここが壊れている

さらに黄は s2.read-floor（読むために必要な最低予備動作長・暫定18F）とも衝突する。最低長で下から抑えると、黄は「絶対的に短い」のではなく「他より短い」になる。初見のプレイヤーは比べる材料を持っていないので、色を絶対値として読めない。受け入れ条件「初見」に直接効く。

重大 C 容量配分の単位が、どこにも書かれていない

13,312 bytes は ZIP のサイズ。一方、容量配分の表はモジュールごとに「2.2〜2.8KB」のように割り当て、合計 8.3〜11.2KB・自主ゲート 11.8KB と 13,312 bytes の隣に並べている。この KB がソース由来なのか ZIP 由来なのかが書かれていない。

  • ZIP バイトだとすると、圧縮は全体で効くのでモジュール単位に按分できない（配分が無意味）
  • ソースバイトだとすると、13,312 bytes と直接比べられない（比較が無意味）

どちらに解釈しても表が壊れる。しかもこの数字はプロジェクトで最も影響が大きい制約であり、duel と read の両方の「継承する制約」に確定値として降りる予定になっている。

要確認 D 「戦闘座標は横軸1本だけ」と「ジャンプで越える」

1.7 は「戦闘座標は横軸1本だけ」「奥行きを持たない」とする。一方 1.4 は回答手段にジャンプを挙げ、「ジャンプで越える」と書く。

越えるには縦方向の座標が要る。1.7 が否定しているのは Z軸（奥行き）なので、おそらく Y軸（高さ）は存在する意図だが、「横軸1本だけ」という文はそう読めない。実装者が最初に止まる箇所。

要確認修正済み E 日数の直書きが古くなっていた

3 と 7-1 が「残り13日」と書いていた（8/31 時点の数）。実際は11日。この文書は残り日数を根拠に判断を下している箇所が複数あり（ボス体数・完成範囲・打ち切り判断）、古い日数はその前提を静かに崩す。締切日時を書く形へ直した。
