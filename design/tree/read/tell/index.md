## 2. なぜ要るのか

**予告が読めないと、`duel` の公平性が全部無駄になる。**
`gen` は「この技はジャンプで越えられる」と検査までして保証するが、
**プレイヤーに危険範囲が見えなければ、越えるべき瞬間が分からない。**

**そして「読める」は主観ではなく検査できる。**
親が受け入れ条件を5つ割り当てたのは、
**`tell` が `read` の課題そのものを引き受けている**からである。

## 3. 誰が使い、誰が影響を受けるか

- **審査員・投票者**。初見・説明を読まない。**`tell` が落とせば数十秒で閉じられる**
- **色覚特性のあるプレイヤー**。不変条件11 が直接効く
- **`duel`**（親経由）: `tell` が「この予告では読めない」と判断したら、
  **知覚の下限を `boundary_request` で `read` → 根へ返す。**根が値を変えると生成が変わる
- **`frame`**: `r1` で画面状態と描画領域を渡すだけ。`tell` からは何も返さない

## 4. 終わったとどうやって分かるか（受け入れ条件）

- [ ] **予告と判定が一致する**（主担当）:
      **描画に渡した危険範囲の座標が、`s1` の値とビット単位で同一。**
      判定: 全フレームで比較して差異0件。加えて
      **`tell` に危険範囲を計算するコードが1行も無い**ことをコードで確認

- [ ] **色を取り除いても遊べる**（主担当）:
      色を輝度のみのグレースケールへ置換しても、
      「どこが危険か」「いつ発生するか」が読める。
      判定: グレースケール版で1体目を通しプレイし、**被弾がカラー版の 1.5倍以内**

- [ ] **テーマ**（主担当）:
      同じグレースケール検査で、**1体目の初見プレイの被弾が有意に増える**ことを示す。
      **上が「読めること」、こちらが「色が効いていること」**

- [ ] **初見**（主担当）:
      ルールを知らない人が説明文を読まずに操作を理解し、最初の敗北まで到達し、
      なぜ負けたかを自分の言葉で言える。判定は根の 4 のまま

- [ ] **知覚の下限の検証**（主担当）:
      予備動作 18F で予告の出現を検出し種類を識別できる。同時2件でも読み分けられる。
      判定: **実際の予告語彙で**、18F の予告を10回提示し
      制作者以外の1人が**8回以上正しく言える**こと。
      **不成立なら `boundary_request` で `read` へ返す**

- [ ] **容量**: **4,600 inlined bytes 以内**

## 5. 変えてはいけない前提

1. 根の不変条件12件。とくに **8**・**11**・**12**
2. **`read` は危険範囲を計算しない**（`read` の不変条件8）。
   **「描画のために少し補正する」こともしない**
3. **色を使わない手がかりを常に2つ以上出す**（同 9）
4. **`s1` を読むだけ。書き換えない**（`read` の親に残すもの1）
5. **7色の語彙**（同 3）。色と特性の対応を変えない
6. **描画順序**（同 4）: 背景 → 予告 → 弾 → プレイヤー → ボス → 効果 →（HUD は `frame`）
7. **内部解像度 640×360・床 Y=307**（同 5）

**`tell` 自身の不変条件**（このノードで著述）

8. **色を決めるのは `palette` だけ。**`telegraph` も `actors` も色値を直書きしない。
   散らばるとグレースケール検査が通せない
9. **`telegraph` と `actors` は互いを呼ばない。**色は必ず `palette` 経由（`t1`/`t2`）で得る。
   共有するのは `s1` と親の定数だけ

## 6. 決めないこと・任せること

**深さ3または実装が決めてよい**

- 具体的な色値（実装は7色のパレットを持つ）
- 予告の充填の仕方（実装は不透明度 0.08 → 0.28）
- 枠線を描くか、塗りだけか
- プレイヤーとボスの描き方（実装は棒人間と矩形）
- 背景の作り方（実装はグラデーション ＋ 星 ＋ 柱）
- 火花・画面揺れの量

**今回は決めない**

- 画像ファイルを持つこと（不変条件12）
- 色以外の手がかりを減らすこと（不変条件9）

## 7. 分からないこと・仮置きしていること

1. **知覚の下限 18F は現状どの技も踏まない。**実装の最短は 24F。
   **18F が妥当かは、検証用の技を手で作らないと測れない**（親の 7-2 から引き継ぎ）

2. **グレースケール検査の閾値 1.5倍に根拠が無い**（親の 7-3 から引き継ぎ）。
   変えるなら `boundary_request`

3. **交代を削ると `drawParty()` の控え描画が消え、画面下部が空く**（親の 7-4）。
   何に使うかは決めていない

4. **色の優先順が実装にある。**実装の `attackColor()` は
   高威力 → 追尾 → 高速 → 長射程 → 多段 の順で1色を選ぶ。
   **1技が複数の特性を持つとき、どれを見せるかの判断**である。
   **`palette` の担当だが、順序の根拠は実装に書かれていない**
