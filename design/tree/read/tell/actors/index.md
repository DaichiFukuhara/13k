## 親からの振り分け

- **責任**: プレイヤー・ボス・弾・効果・背景を描き、姿から性格を推測させる
- **詳細化の対象**: 親の本文1の「姿から性格を推測させる」。根の 1.1 の1行目
  （武器シルエットの太さ・長さ・主色・緑の輪郭）、1.7（16:9 の1画面固定）
- **継承する制約**: 根12件＋`read` 3件＋`tell` 2件。とくに
  **12**（画像ファイル・外部フォントを持たない。描画は実行時に生成する）、
  **「色を決めるのは `palette` だけ」**。
  `s1` を読むだけ。描画順序（`tell` の親に残すもの4）。解像度（同5）。
  **操作キャラは1人**（根の親に残すもの8。控えの描画を持たない）。
  容量の目安 **2,400 inlined bytes**
- **割り当てられた受け入れ条件**: 初見（主）、色を取り除いても遊べる（規則の実行）
- **uses_seams**: `r1.screen-state`, `t2.color-result`（`palette` から色と冗長化の指示）
- **提供する seam**: `t1.color-request`（`palette` へ）
- **parent_decision_ref**: `tell@2026-09-05-decision-4` ＋ `tell@2026-09-05-split-4`

## 1. これは何を決めるものか

**戦闘画面に映る「もの」の姿。**

### 1.1 描くもの

| 対象 | `s1` から使う値 | 描き方 |
| --- | --- | --- |
| **背景** | なし（固定） | グラデーション ＋ 星 ＋ 柱 ＋ 床の線 |
| **プレイヤー** | 座標 / 接地・滞空 / 行動 / 無敵中か | 棒人間。ロール中は傾ける・半透明にする |
| **ボス** | 座標 / 向き / 状態 / 外見（主色・武器・防御） | 頭 ＋ 胴 ＋ 脚 ＋ **武器シルエット** ＋ 7色の帯 |
| **弾** | 座標 / 所有者 / 色 | 小さな矩形 |
| **効果** | 被弾・撃破のイベント | 火花（当たり判定を持たない） |

**すべて実行時に生成する。**画像ファイルを持たない（不変条件12）。

**色は `palette` から受ける**（`tell` の不変条件8）。
`t1.color-request` で**対象の種別**（ボスの主色 / 弾の所有者 / 防御の輪郭 / 火花）**と
「それが何を示すか」**を渡し、`t2.color-result` で**色値と冗長化の指示**を受ける。
**色値を直書きしない。**

### 1.2 姿から性格を推測させる（根の 1.1 の1行目）

**戦闘が始まる前に、ボスの姿だけで次が読める。**

| 見た目 | 示すもの | `s1` の値 |
| --- | --- | --- |
| 武器シルエットの**太さ** | 威力 | 固有技の威力（実装は形状で分岐） |
| 武器シルエットの**長さ** | 射程 | 固有技の射程（実装は `28 + 射程 × 8`） |
| **主色** | 最も危険度へ寄与した特性 | `gen` が決めた主色 |
| **緑の輪郭**の有無 | 防御能力 | 防御能力の種別 |
| **7色の帯**（胴に並ぶ） | 主色がどれかを明示する | 主色の添字 |

**これが根の 1.6「見た目が生成結果の関数になっている」の実効化である。**

> 🧭 **7色の帯は、色の語彙そのものを画面に置いている。**
> 7本並んでいて1本だけ明るいので、
> **「この色は7つのうちの1つだ」という語彙の存在が、説明なしに伝わる。**
> 初見の受け入れ条件に直接効く。（2026-09-04・実装から）

### 1.3 状態を姿で示す（色に依存しない手がかり）

| 状態 | 姿 |
| --- | --- |
| ロール無敵中 | **半透明**になる ＋ 前傾する |
| パリィ受付中 | 前方に**弧**を描く（受付中だけ濃く） |
| ボスの体勢崩し | ボスが**傾く** |
| ボスの構え（SHIELD） | 前面に**板**が出る |
| BARRIER 有効 | ボスを囲む**輪** |

**すべて色を使わずに読める。**`palette` の冗長化の表（同ノード 1.4）の実行側である。

### 1.4 削るもの（実装からの差分）

| 実装にあるもの | 扱い | 根拠 |
| --- | --- | --- |
| **控え2人の描画**（`drawParty()` の半透明の2体） | **削る** | 根の `親に残すもの8`「操作キャラは1人」 |
| **キャラごとの武器**（角 / 剣 / 短剣の描き分け） | **1つにする** | 同上 |

**出所は実装**（`drawPerson()` / `drawBoss()` / `drawParty()` / `background()`）。
[`design/AS_BUILT.md`](../../../../AS_BUILT.md) §6・§7。

## 2. なぜ要るのか

**根の 1.1 は、1戦のループの1番目に「姿から性格を推測する」を置いている。**
予備動作を見る前に、**姿だけで身構え方が変わる**という設計である。

**これが無いと、初見のプレイヤーは1発目を必ず食らう。**
食らってから学ぶゲームにはなるが、**根の 1.9 の1点目
（初見では緊張し、一度見れば理解できる）の「緊張」が生まれない。**
緊張は「何か来そうだ」と分かっているときにしか起きない。

## 3. 誰が使い、誰が影響を受けるか

- **審査員・投票者**。**画面を開いた瞬間に見るのがこれ**
- **色覚特性のあるプレイヤー**。1.3 の状態表示が色に依存しないことが効く
- **`palette`**: 色を得るために呼ぶ。冗長化の規則の実行側でもある
- **`duel.fight.avatar`**（親経由）: 交代を削る決定が、ここの控え描画の削除に直結する

      ルールを知らない人が説明文を読まずに操作を理解し、最初の敗北まで到達し、

- [ ] **姿から性格が読める**（`初見` の `actors` 側の分担）:

      当てられる。**

      **威力と射程の大小を7回以上正しく言える**こと

      > 🧭 **これが `actors` の一番の仕事である。**
      > 予告が読めることは `telegraph` が引き受けるので、
      > **`actors` は「予告が出る前に読めること」を引き受ける。**（2026-09-04）

- [ ] **状態が色なしで読める**:
      グレースケール版で、**ロール無敵中・パリィ受付中・体勢崩し・構え中**を見分けられる。
      判定: 各状態を5回ずつ提示し、**8割以上正しく言える**こと

- [ ] **控えが描かれない**:
      **画面に操作キャラが1人しか出ない。**
      判定: `drawParty` 相当の複数体描画コードが0件

- [ ] **画像ファイルを持たない**（不変条件12）:
      判定: ビルド成果物に画像・フォントのバイナリが0件（`index.html` 1枚だけ）

- [ ] **容量**: **2,400 inlined bytes 以内**

## 5. 変えてはいけない前提

1. 根の不変条件 **12**（画像ファイル・外部ライブラリを持たない。描画は実行時に生成する）
2. **色を決めるのは `palette` だけ**（`tell` の不変条件8）。色値を直書きしない
3. **色を使わない手がかりを常に2つ以上出す**（`read` の不変条件9）
4. **操作キャラは1人**（根の親に残すもの8）。控えを描かない
5. **描画順序**: 弾の次、効果の前（`tell` の親に残すもの4）
6. **16:9 の1画面固定。スクロールしない**（根の 1.7）
7. **`s1` を書き換えない**

## 6. 決めないこと・任せること

**実装が決めてよい**

- プレイヤーとボスの造形（実装は棒人間と矩形）
- 背景の作り方（実装はグラデーション ＋ 星70個 ＋ 柱 ＋ 床の線）
- 火花の量・寿命・重力（実装は 8〜22個・16〜31F）
- 画面揺れの大きさと減衰（実装は 0.82 倍ずつ）
- 武器シルエットの具体的な描き方
- 7色の帯の位置と大きさ

**今回は決めない**

- 画像ファイルを持つこと
- 奥行き（Z）の表現を当たり判定に使うこと（根の 1.7。背景は演出専用）

## 7. 分からないこと・仮置きしていること

1. **武器シルエットの「太さ＝威力」が実装に無い。**
   実装は**形状**で太さを分けている（叩きつけは太い線、それ以外は細い線）が、
   **威力では分けていない。**
   `palette` の冗長化の表の「高威力 → 厚み」の穴（`palette` の 7-4）と同じ問題である。

   **仮置き**: 武器シルエットの太さを**固有技の威力**に比例させる。`provisional: true`。
   **受け入れ条件「姿から性格が読める」がこれを要求している**ので、作る必要がある

2. **控えを削ると画面下部が空く**（`read` の 7-4 から引き継ぎ）。
   実装は3人ぶんの HP・スタミナバーを下端に置いていた。
   **HUD は `frame` の担当なので、`actors` では決められない**

3. **「姿から性格が読める」の判定に静止画10枚が要る。**
   生成物なので**シードを選べば作れる**が、
   **威力と射程が極端な個体を選ぶと簡単すぎる。**選び方を決めていない。
   仮置き: ランダムに引いた10体を使う

4. **プレイヤーの造形を1つに決めていない**（`avatar` の 7-4 と対応）。
   実装の3キャラは角 / 剣 / 短剣で描き分けている。
   **どれを残すかは `avatar` の攻撃の選択と揃える必要がある**が、
   `actors` は `avatar` を知らない。**`s1` の操作割当と行動から読める範囲で描く**
