# actors（システム: プレイヤー・ボス・弾・効果・背景を描き、姿から性格を推測させる）

## 2026-09-08 現行差分 — 6形状の構え・発生・硬直を姿で分ける

`actors@2026-09-08-decision-4`。親は `tell@2026-09-08-decision-5 / split-5`。
この1〜7を優先し、未変更事項だけ基準版を継承する。深さ3の葉のため分割しない。
根に記録された設計編集・サブエージェント実装・検証の作業許可に基づく。
具体版の人間決定承認と正式precheckは未記録。旧approval-3で代用しない。

### 1. 決めるもの

人物は兜、短いケープ、面のある胴、分かれた脚、武器で輪郭を作る。
同じ描画関数を主人公とボスへ使い、実座標を原点として向きだけ反転する。
SWEEPは引いて低く払う、THRUSTは引いて水平へ突く、SLAMは頭上から下へ振る、
CHARGEは低く構えて前傾する、SHOTは引いて前へ放つ、RAINは頭上へ掲げる。
全形状のrecoverは腕を下げ重心を落として通常姿勢へ戻す。staggerはさらに頭と腕を落とす。
windの進行は主人公m.windとボスWIND[m[W]-1]を用い、段間は腕を戻す。
武器の短い軌跡は装飾であり危険範囲ではない。射程と威力は武器の長さと太さへ写す。

### 2. なぜ要るか

従来の棒人間と固定された武器からは、攻撃前と反撃できる時間が読み取りにくい。
身体と腕の輪郭を変え、色や説明文だけに依存せず時間の区切りを示す。

### 3. 利用者

初見と再挑戦のDesktopプレイヤー。trialでも同じ描画で技の使用感と標的を確認する。

### 4. 受け入れ条件

- [ ] A1 / T1: 全6形状×主人公/ボスのwind、active、recoverを静止画で区別でき、ボスstaggerが別姿勢になる。
- [ ] A2 / T1,T5: 実タイマーで段間と最終硬直を区別し、連続使用で前の姿勢が残らない。
- [ ] A3 / T4,T5: fight/trial/pause復帰で実座標に描き、反復描画が戦闘状態を変更しない。命中成功を姿勢から推測しない。
- [ ] A4 / T6: 灰色でも姿勢の差が残り、外部画像無し。統合ZIPは13,312 bytes以内。
- [ ] A5: 人間による初見理解、18F知覚、威力/射程の認識は未検証なら未検証と残す。

### 5. 不変条件・seam

編集はgame.jsのdrawPerson/drawHero/drawBossのみ。p/bの座標、向き、技、行動、phase、timerを読む。
HP/判定/性能/タイマー/候補/戦績を変更しない。判定座標は既存boxPlayer/boxBoss/moveRectが正本。
640×360、床Y=307、既存描画順序、t1/t2の色分類、s1/r1の片方向契約を継承する。
色はHERO.col/PAL/HOLD_COLと既存の中立色を用いる。trialの退避情報に依存しない。
武器と身体の装飾は当たり判定を動かす許可ではなく、攻撃矩形の別展開を持たない。

### 6. 実装へ任せるもの

具体的な腕/脚の座標、角度、輪郭、短い残像。約900 ZIP bytes追加を目安とし、容量は根で統合実測する。
装飾よりphaseの判別を優先する。背景/弾/効果と他の描画関数は今回変更しない。

### 7. 未確定・検証の限界

静止画と非変更検査は人間知覚の代替ではない。初見と18F知覚の合否は未検証。
runtimeの段間/最終recoverと描画の食い違いは親へ返し、描画から更新器を修正しない。

## 1. これは何を決めるものか

**戦闘画面に映る「もの」の姿。**

### 1.1 描くもの

| 対象 | `s1` から使う値 | 描き方 |
| --- | --- | --- |
| **背景** | なし（固定） | グラデーション ＋ 星 ＋ 柱 ＋ 床の線 |
| **プレイヤー** | 座標 / 接地・滞空 / 行動 / 無敵中か | 棒人間。ロール中は傾ける・半透明にする |
| **ボス** | 座標 / 向き / 状態 / 外見（主色・武器・防御） | 頭 ＋ 胴 ＋ 脚 ＋ **武器シルエット** ＋ 7色の帯 |
| **弾** | 座標 / 所有者 / 色 | 小さな矩形 |
| **効果** | 被弾・撃破のイベント | 火花（当たり判定を持たない） |

**すべて実行時に生成する。**画像ファイルを持たない（不変条件12）。

**色は `palette` から受ける**（`tell` の不変条件8）。
`t1.color-request` で**対象の種別**（ボスの主色 / 弾の所有者 / 防御の輪郭 / 火花）**と
「それが何を示すか」**を渡し、`t2.color-result` で**色値と冗長化の指示**を受ける。
**色値を直書きしない。**

### 1.2 姿から性格を推測させる（根の 1.1 の1行目）

**戦闘が始まる前に、ボスの姿だけで次が読める。**

| 見た目 | 示すもの | `s1` の値 |
| --- | --- | --- |
| 武器シルエットの**太さ** | 威力 | 固有技の威力（実装は形状で分岐） |
| 武器シルエットの**長さ** | 射程 | 固有技の射程（実装は `28 + 射程 × 8`） |
| **主色** | 最も危険度へ寄与した特性 | `gen` が決めた主色 |
| **緑の輪郭**の有無 | 防御能力 | 防御能力の種別 |
| **7色の帯**（胴に並ぶ） | 主色がどれかを明示する | 主色の添字 |

**これが根の 1.6「見た目が生成結果の関数になっている」の実効化である。**

> 🧭 **7色の帯は、色の語彙そのものを画面に置いている。**
> 7本並んでいて1本だけ明るいので、
> **「この色は7つのうちの1つだ」という語彙の存在が、説明なしに伝わる。**
> 初見の受け入れ条件に直接効く。（2026-09-04・実装から）

### 1.3 状態を姿で示す（色に依存しない手がかり）

| 状態 | 姿 |
| --- | --- |
| ロール無敵中 | **半透明**になる ＋ 前傾する |
| パリィ受付中 | 前方に**弧**を描く（受付中だけ濃く） |
| ボスの体勢崩し | ボスが**傾く** |
| ボスの構え（SHIELD） | 前面に**板**が出る |
| BARRIER 有効 | ボスを囲む**輪** |

**すべて色を使わずに読める。**`palette` の冗長化の表（同ノード 1.4）の実行側である。

### 1.4 削るもの（実装からの差分）

| **控え2人の描画**（`drawParty()` の半透明の2体） | **削る** | 根の `親に残すもの8`「操作キャラは1人」 |
| **キャラごとの武器**（角 / 剣 / 短剣の描き分け） | **1つにする** | 同上 |

## 2. なぜ要るのか

**根の 1.1 は、1戦のループの1番目に「姿から性格を推測する」を置いている。**
予備動作を見る前に、**姿だけで身構え方が変わる**という設計である。

**これが無いと、初見のプレイヤーは1発目を必ず食らう。**
食らってから学ぶゲームにはなるが、**根の 1.9 の1点目
（初見では緊張し、一度見れば理解できる）の「緊張」が生まれない。**
緊張は「何か来そうだ」と分かっているときにしか起きない。

## 6. 決めないこと・任せること

**実装が決めてよい**

- プレイヤーとボスの造形（実装は棒人間と矩形）
- 背景の作り方（実装はグラデーション ＋ 星70個 ＋ 柱 ＋ 床の線）

**今回は決めない**

- 画像ファイルを持つこと
- 奥行き（Z）の表現を当たり判定に使うこと（根の 1.7。背景は演出専用）

## 7. 分からないこと・仮置きしていること

1. **武器シルエットの「太さ＝威力」が実装に無い。**
   実装は**形状**で太さを分けている（叩きつけは太い線、それ以外は細い線）が、
   **威力では分けていない。**
   `palette` の冗長化の表の「高威力 → 厚み」の穴（`palette` の 7-4）と同じ問題である。

   **仮置き**: 武器シルエットの太さを**固有技の威力**に比例させる。`provisional: true`。
   **受け入れ条件「姿から性格が読める」がこれを要求している**ので、作る必要がある

2. **控えを削ると画面下部が空く**（`read` の 7-4 から引き継ぎ）。
   実装は3人ぶんの HP・スタミナバーを下端に置いていた。
   **HUD は `frame` の担当なので、`actors` では決められない**

3. **「姿から性格が読める」の判定に静止画10枚が要る。**
   生成物なので**シードを選べば作れる**が、
   **威力と射程が極端な個体を選ぶと簡単すぎる。**選び方を決めていない。
   仮置き: ランダムに引いた10体を使う

4. **プレイヤーの造形を1つに決めていない**（`avatar` の 7-4 と対応）。
   実装の3キャラは角 / 剣 / 短剣で描き分けている。
   **どれを残すかは `avatar` の攻撃の選択と揃える必要がある**が、
   `actors` は `avatar` を知らない。**`s1` の操作割当と行動から読める範囲で描く**
