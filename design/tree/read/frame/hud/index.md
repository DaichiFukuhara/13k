## 1. これは何を決めるものか

**戦闘中、常に画面に出ている数値。**

### 1.1 出すもの

| 項目 | 位置 | 形 | `s1` の値 |
| --- | --- | --- | --- |
| **ボス HP** | 上端・長いバー | 横長のバー | ボス HP / 最大値 |
| **ボス体勢** | ボス HP の直下・**細いバー** | 横長の細いバー | 体勢 / 最大値 |
| ボスの名前 | 上端左 | テキスト（**主色**） | 外見から作った異名 |
| 防御能力 | 上端右寄り | テキスト | 防御能力の種別 |
| **プレイヤー HP** | 下端・短いバー | 横長のバー | HP / 最大値 |
| **プレイヤースタミナ** | HP の直下・**細いバー** | 横長の細いバー | スタミナ / 100 |
| シード | 上端右 | テキスト（36進） | シード |
| 技名と数値 | 中央上寄り・**一時表示** | テキスト | 現在技の形状名・威力・射程 |

### 1.2 色に依存しない区別（不変条件11）

**4本のバーは、色ではなく位置と太さで区別する。**

| バー | 位置 | 太さ |
| --- | --- | ---: |
| ボス HP | **上端** | 太い（8px） |
| ボス体勢 | 上端・HP の下 | **細い**（4px） |
| プレイヤー HP | **下端** | 太い（5px） |
| プレイヤースタミナ | 下端・HP の下 | **細い**（3px） |

**「上＝敵 / 下＝自分」「太い＝命 / 細い＝崩れ・資源」。**
**グレースケールにしても4本とも区別できる。**

> 🧭 **これが `hud` の受け入れ条件「色を取り除いても遊べる」の実効化である。**
> 色で区別していたら、グレースケールで4本が同じ灰色の帯になる。
> **位置と太さで区別すれば、色は「どのボスか」の追加情報に降格できる。**（2026-09-04）

### 1.3 スタミナが見えることの意味

**根の 1.5 は「スタミナの残りを見て、次を回避に使うか攻撃に使うかを決める」を
1戦のループの5番目に置いている。**

**バーが見えないと、この判断が成立しない。**
スタミナは根の設計で**唯一の資源**なので、HUD の中で最も重要である。

| キャラ名の表示（3つ） | **1つまたは削除** | 同上 |

**下端が空く**（`read` の 7-4）。**何に使うかは決めない**（6 へ）。

**出所は実装**（`hud()` / `bar()`）。[`design/AS_BUILT.md`](../../../../AS_BUILT.md) §7。

## 2. なぜ要るのか

**受け入れ条件「初見」は「最初の敗北まで到達する」ことを要求する。**
**残り HP が見えなければ、いつ死ぬか分からないまま死ぬ。**
そうなると「なぜ負けたか」が「気づいたら死んでいた」になる。

**体勢バーも同じ理由で要る。**体勢は根の共通語彙にある「ボスの第2の耐久値」で、
0 になると大きな隙が生まれる。**見えないと、パリィが何のためにあるか分からない。**

## 3. 誰が使い、誰が影響を受けるか

- **プレイヤー**。1戦のあいだ常に見ている
- **色覚特性のあるプレイヤー**。1.2 の区別が直接効く
- **`duel.fight.avatar`**（親経由）: 交代を削る決定が、バーの本数に直結する
- **`screens`**: 結果表示で同じ数値を使うが、**互いを知らない**（両方 `s1` を読む）

## 5. 変えてはいけない前提

1. 根の不変条件 **11**（色だけに依存させない）、**12**（画像・外部フォントを持たない）
2. **色を決めるのは `palette` だけ**ではない — **`hud` は `frame` の子であり `tell` の外**である。
   ただし**7色の語彙は `read` の表を使う**（`frame` の親に残すもの3）

   > ⚠️ **`palette` は `tell` の子なので、`hud` からは兄弟ですらない**（別の部分木）。
   > **`hud` は色の語彙の表を親から継承して直接使う。**
   > 色を1箇所に閉じる規約は `tell` の内部規約であって、`frame` には掛かっていない。
   > **これは設計上の非対称であり、7-3 に記録した**

3. **`s1` を読むだけ。書き換えない**
4. **画面領域の分割**（`frame` の親に残すもの4）: 上端 0〜48 / 下端 325〜355
5. **操作キャラは1人**（根の親に残すもの8）。バーは1組
6. **描画順序**: HUD は最前面に近い（`read` の親に残すもの4）

## 6. 決めないこと・任せること

**実装が決めてよい**

- バーの正確な座標・幅・高さ（実装は上端 390×8 / 390×4、下端 108×5 / 108×3）
- テキストのサイズと書体（システムフォントのみ）
- 技名の表示時間（実装は予備動作の長さと 55F の短いほう）
- シードの表示形式（実装は36進6桁）
- **交代を削って空いた下端をどう使うか**（空けたままでよい）
- スタミナ不足の閾値表示を足すかどうか

**今回は決めない**

- 画像ファイルを持つこと
- HUD を消せるようにすること（設定 UI は作らない）

## 7. 分からないこと・仮置きしていること

1. **交代を削ると下端が空く**（`read` の 7-4 から引き継ぎ）。
   実装は3列（各 108px 幅）で下端 20〜340px を埋めていた。
   **1組にすると 2/3 が空く。**
   仮置き: 空けたままにする。`provisional: true`。
   **バーを長くするとプレイヤーの HP が「多い」ように誤読される**恐れがあるので、
   長さは据え置く

2. **スタミナ不足が「足りない」と分かる表示が実装に無い。**
   実装は残量バーだけで、**「この行動には足りない」は行動が始まらないことでしか分からない。**
   受け入れ条件がそれを要求しているので、**閾値の目盛りか色の変化が要る。**
   ただし**色に依存させられない**（不変条件11）ので、目盛りか点滅になる

3. **色の語彙を `hud` が直接使うのは、`tell` の規約と非対称である。**
   `tell` では色を `palette` 1箇所に閉じたが、`frame` にはその規約が無い。
   **グレースケール検査は `hud` にも掛かる**ので、
   **`hud` の色も1箇所にまとめたほうがよい可能性がある。**
   `frame` へ `boundary_request` を上げるかは、実装してから判断する

4. **ボスの名前を主色で描いているが、色以外の手段が無い。**
   名前は「異名」（色名＋武器名）なので、**テキスト自体が色を語っている** —
   グレースケールでも "CRIMSON BLADE" と読める。**冗長化としては成立している**
