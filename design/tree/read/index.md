- **責任**: 何が・いつ・どこへ来るかを、色と形と時間で同時に伝え、
  見えているものと当たるものを一致させる

- **詳細化の対象**:
  - `1.1` 予告が何を同時に示すか
  - `1.6` 虹7色の語彙
  - `1.7` 1画面固定・X / Y / Z の扱い
  - `1.9` の1点目（初見で緊張し、一度見れば理解できる）

- **継承する制約**: 根の不変条件12件すべて。特に
  - **8** 予告した危険範囲と実際の当たり判定は、同一の定義から作る
  - **11** 色だけに依存させない
  - **12** 画像・音声ファイル・外部ライブラリを持たない（描画と音は実行時に生成）
  - 形状定義を**読むだけ**で独自に持てないこと（親に残すもの3）
  - **知覚の下限**（最低予備動作長 18F・同時予告上限 2）は根が置いた**仮の前提**
    （`provisional: true`・親に残すもの4）。
    **この値を実際の予告語彙に対して検証するのが `read` の担当。**
    成立しなければ `boundary_request` で根へ返す
  - 容量の目安 **9,500 inlined bytes**（**シェル（`index.html`・CSS・起動）を含む**・
    設計時見積もり・親に残すもの9）。実測と再調停は実装段階へ `deferred`
  - 実装基盤は `deferred`（再開条件: 最初の深さ2の分割承認まで）なので、
    **深さ1では基盤を前提にしない**

- **割り当てられた受け入れ条件**: テーマ、初見（主）、学習（前提としての可読性）

- **uses_seams**: `s1.presentation-state`（`duel` から）。
  技表示 / 戦闘状態 / ライフサイクル / 結果表示 / 操作割当。
  **危険範囲は正本を読むだけで、表示用の形を独自に持たない**

- **提供する seam**: なし（`read` は兄弟へ何も渡さない）

- **開く順序**: **2番目**（`duel` の `s1` が親に権威化されてから）
