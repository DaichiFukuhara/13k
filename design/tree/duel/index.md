## 1. これは何を決めるものか

<!-- 深さ1: 課題の範囲と、それに対する解決法 -->

**課題の範囲**: シードから生成された敵と、1人のプレイヤーが**1戦のあいだ噛み合う条件**と、
それを**構造として保証する仕組み**を決める。

含むもの: 何を生成し何を生成しないかの実効化 / 危険度予算と禁止組み合わせ /
危険包絡と安全席の検査 / プレイヤーの4つの回答手段とスタミナ / 当たり判定 /
ボスの行動選択 / ランの構造。

含まないもの: 画面に何をどう出すか（`read` の担当）/ 具体的な数値（深さ2以降へ委任）。

### 解決法: 「公平さを祈らず、生成のたびに検査する」

根の `1.3` は公平性を**危険度予算**で担保しようとしていたが、
Codex の前検査で**予算だけでは不変条件10（反射神経に依存しない回答を最低1つ持つ）を
保証できない**ことが分かった。予算は「強さの総量」を揃えるだけで、
「抜け道があるか」は測っていないからである。

そこで `duel` は、**保証を予算から検査へ移す**。

| 層 | 役割 | 保証するもの |
| --- | --- | --- |
| 1. **危険度予算** | 技の強さの総量を揃える | ボスごとの**難易度の一貫性** |
| 2. **禁止組み合わせ** | 検査を通りにくい組を最初から作らない | **引き直し回数の削減**（保証ではなく最適化） |
| 3. **安全席の検査** | 生成された1技ごとに、抜け道の存在を機械的に確かめる | **不変条件10**（公平性の本体） |
| 4. **選択時の条件** | その技を「今」出してよいかを、プレイヤーの位置で判定する | **利用可能性**（席が存在するだけでなく、座れていること） |
| 5. **フォールバック** | 引き直し上限（8回）を超えたら固定技へ | **停止性**（特定シードで生成が終わらないことの防止） |

**この5層が `duel` の解決法の骨格である。**1〜2 は既に根が書いており、
`duel` が新しく引き受けるのは **3・4・5 を実装可能な形へ落とすこと**。

### 生成は決定論的でなければならない

不変条件9（同じシードは同じ敵を再現する）は、**検査と引き直しを含めて決定論的**
であることを要求する。引き直しが乱数の状態を進めるので、
**シードから生成器の全状態が再現できる**必要がある。

- 生成に使う乱数は**シードから導出した1本の系列**だけ。時刻・端末・実行回数に依存しない
- 検査の結果も決定論的（浮動小数の丸めに依存しない形で判定する）
- **リトライ時は生成をやり直さない。**生成結果をそのまま再利用する（不変条件9）

## 2. なぜ要るのか

**今どうなっているか**: 根は「生成された攻撃には必ず抜け道がある」と宣言しているが、
**それを確かめる主体が居ない。**根の `1.3` は禁止組み合わせを列挙する形だったが、
Codex の前検査3回で**列挙では塞ぎきれない**ことが繰り返し示された
（黄×藍、黄×紫、接近後攻撃、一度だけ照準を合わせる技、安全席が排他的な組）。

**何が困るか**: 抜け道の無い技が1つでも生成されると、
**受け入れ条件「初見」（なぜ負けたかを自分の言葉で言える）が壊れる。**
プレイヤーは「理不尽だった」としか言えず、それは学習ではない。
しかも生成物なので、**制作者がテストで踏むとは限らない。**
特定のシードでだけ壊れる不具合になり、審査員が引く可能性がある。

**祈りでは足りない。**列挙を増やすたびに新しい抜け道が見つかったのが、前検査3回の記録である。

## 4. 終わったとどうやって分かるか（受け入れ条件）

親から `学習（主）` と `初見（前提としての公平性）` を割り当てられた。
**親条件の写しではなく、`duel` で検査可能な形にする。**

- [ ] **決定論**（親条件「学習」の前提）:
      **同一シードから2回生成した結果が、ビット単位で一致する。**
      技構成・数値・修飾子・山札・外見・第2形態変異のすべてを含む。
      判定: 1,000 個のシードで2回ずつ生成し、シリアライズしたバイト列を比較して全一致

- [ ] **公平性**（親条件「初見」の前提）:
      **生成されたすべての技が、安全席の検査を通っている。**
      判定: 10,000 個のシードでボスを生成し、全技について
      「危険包絡をプレイヤー半幅で膨張させ、画面内の有効中心位置から差し引いた残りが
      プレイヤー1人分以上の幅を持つ」ことを検査して、**違反0件**

- [ ] **停止性**:
      **どのシードでも生成が有限時間で終わる。**
      判定: 上の 10,000 シードで、引き直し回数が8回を超えた場合に
      フォールバック技が採用されていること。無限ループ・例外が0件

- [ ] **利用可能性**（選択時条件の実効化）:
      **黄の技が選ばれた瞬間、プレイヤーは必ずその技の安全席の中に居る。**
      判定: 自動プレイ（ランダム入力）で 1,000 戦を走らせ、
      黄の技が発動した全フレームについて、発動時のプレイヤー中心が安全席内にあったことを記録。違反0件

- [ ] **学習が起きる**（親条件「学習」の本体・`duel` 側の分担）:
      **同じシードへの再挑戦で、被弾回数が減る余地がある。**
      判定: 同一シードのボスに対し、
      (a) 完全ランダム入力と (b) 技の山札を知っている台本入力 を各20回走らせ、
      **(b) の平均被弾回数が (a) の 50% 以下**であること。
      これが成立しないなら、技を覚えても勝率が上がらない設計になっている

> 🧭 **AI**: 「学習が起きる」を**台本入力との比較**で測ることにした。
> 人間の被験者を要さないので、根の 7-2（被験者を確保できるか未定）に依存しない。
> 人間による検証は `read` 側の「初見」が引き受ける。（2026-09-03）

## 7. 分からないこと・仮置きしていること

1. **山札に黄の技しか残っていない状況の扱い**（親から引き継いだ未検査事項）。
   選択時条件は「プレイヤーが安全席に居なければ黄以外を選ぶ」だが、
   **黄以外が残っていない場合の振る舞いが決まっていない。**

   **仮置き**: 山札を引き直す（同じ技を再度引ける形にする）。`provisional: true`。
   **深さ2の「ボスの行動選択」で決める。**根へ返す必要は無いと判断した —
   これは山札の設計であって、根の決定（選択時条件そのもの）は変えないため

2. **検査器のコスト**が分からない。危険包絡の計算をフレームごとの離散サンプリングで行うと、
   10,000 シードの検証が実行時間の問題になる可能性がある。
   また実行時（ゲーム内）に走らせるなら、**生成の待ち時間**が発生する。
   仮置き: 生成はタイトル画面またはボス出現前の演出中に行い、体感を隠す

3. **「学習が起きる」の閾値 50% に根拠が無い。**台本入力が完全ランダムの半分以下の被弾、
   という線は直感で置いた。深さ2で実測して調整する可能性がある

4. **容量 18,500 bytes に検査器が収まるか未検証。**生成器と検査器が二重に必要なので、
   `duel` の中で最も削られやすい。**削るとしたら検査の網羅度**（10,000 シード → 全数検査を
   実行時ではなくビルド時に回す等）だが、それは受け入れ条件「公平性」を弱める

5. **根の 1.8（ランの構造）は仮置きのまま。**体数が決まらないと総容量が見積もれない
