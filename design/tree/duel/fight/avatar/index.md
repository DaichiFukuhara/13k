## 1. これは何を決めるものか

**操作キャラ1人の、1フレームぶんの振る舞い。**

**`avatar` は当たり判定を行わない。**自分の矩形と状態を `f1` で `arena` へ渡し、
被弾やパリィ成立は `f3` で受け取るだけである（不変条件8 の実効化）。

### 1.1 1フレームの処理順（順序に意味がある）

| # | 処理 |
| --- | --- |
| 1 | 無敵・スタミナ回復待ちのタイマーを減らす |
| 2 | 各入力を**バッファ**へ移す（ジャンプ 7F / その他 5F） |
| 3 | 実行中の行動のタイマーを進め、発生・終了フレームを処理する |
| 4 | 行動が空なら、**ロール → パリィ → 攻撃**の優先順で開始する |
| 5 | ジャンプ入力と**コヨーテタイム**を処理する |
| 6 | 重力・座標・床・画面端を処理する |
| 7 | 通常時だけボス本体との重なりを押し戻す |

**入力バッファにより、硬直終了の数フレーム前に押したボタンも次の行動になる。**
これが無いと、根の 1.1「攻撃後硬直へ攻撃を差し込む」が反射のゲームになる。

### 1.2.1 所持技（根の 1.10）

**プレイヤーの攻撃は常に1つ。**初期は素手の近接で、
**ボスを倒すたびに、その敵の技へ持ち替えるか選ぶ。**

| 項目 | 値 |
| --- | --- |
| 所持枠 | **1つ。増えない** |
| 攻撃力 | **常に 7**（正規化。ボス側の威力は使わない） |
| 引き継ぐもの | 形状 / 射程 / 予備動作（＝発生F）/ 攻撃後硬直 / 多段 |
| スタミナ消費 | `14 + (4 − 予備動作の段) × 4`（`duel` の本文5 の 13） |
| 初期の素手 | 近接 THRUST 相当・射程 46px・発生 9F・全体 22F・消費 14 |

**発動は既存の攻撃入力（J / Z）と同じ。**別のキーを増やさない
（根の 1.4「回答手段は4つだけ」に攻撃は含まれないが、**入力を増やすと初見が壊れる**）。

**`avatar` は攻撃の判定矩形を作らない。**`f1` で「攻撃中である」ことと
所持技のパラメータを渡し、**展開は `arena` が行う**（`fight` の不変条件8）。

> 🧭 **奪取技も敵の技と同じ展開規則を通る**（`duel` の親に残すもの4）。
> **プレイヤーとボスで別の当たり判定の作り方を持たない。**（2026-09-05）

### 1.3 スタミナ（根の 1.5）

- **ローリング・パリィ・攻撃**がスタミナを食う
- **消費後しばらく回復が止まる**（実装は 30F）
- 足りなければ**行動を開始できない**

**だから「回避し続ける」も「殴り続ける」もできない。**

> ⚠️ **交代を削ると、資源判断の層が薄くなる。**
> 実装は3人分のスタミナを持ち、**控えのほうが回復が速い**（0.5/F 対 0.3/F）ことで
> 交代に資源上の意味を持たせていた。1人になるとその軸が消える。**7-2 で扱う。**

### 1.4 回答手段は4つだけ

| 手段 | 実装での性質 | 反射神経を要求するか |
| --- | --- | --- |
| **移動** | 歩行速度 2.45 px/F。予備動作中に包絡の外へ出る | **しない** |
| **ジャンプ** | 到達 59px・滞空 35F・**空中制御なし**・可変高度（早離しで減速） | **しない** |
| **ローリング** | 24F 中 **4〜14F だけ無敵**。開始直後と終端には判定が残る | する |
| **パリィ** | 22F 中 **4〜9F だけ受付**。失敗すると残りがそのまま硬直 | する |

**上2つが根の 1.4「反射神経を要求しない方法」、下2つが「難しいが反撃しやすい方法」。**
`audit` の検査 B はこの分類をそのまま使う。

## 2. なぜ要るのか

`gen` は「この技はジャンプで越えられる」と**宣言**する。
根の共通語彙は「**宣言と実装が食い違ってはならない**」と定める。
**`avatar` は、その宣言を現実にする側である。**

ジャンプ到達が 59px なら「高さ 57px の SLAM」は越えられるが、
契約の仮値 52px で `audit` が検査していたら**越えられないと判定されて捨てられる。**
**契約と実装がずれると、公平性の検査が嘘になる。**

だから `avatar` は不変条件（`fight` の 10）として、
**±25% の範囲内で値を動かした場合でも「宣言との一致」を再検査する**義務を負う。

## 3. 誰が使い、誰が影響を受けるか

- **プレイヤー**。手触りの大半はここで決まる
- **`arena`**: `f1` を受け取って判定する唯一の相手
- **`gen.audit`**（親経由・間接）: 能力契約を通じて `avatar` の性能に依存する。
  **`avatar` が値を動かすと、`audit` の検査結果が古くなる**
- **`read`**（`arena` 経由）: HP・スタミナ・接地/滞空は `s1` に載る

## 4. 終わったとどうやって分かるか（受け入れ条件）

- [ ] **宣言との一致（前提側の分担）**:
      **能力契約に書かれた各値が、実装の実測と一致する。**
      判定: ジャンプ到達高さ・滞空F・ロール無敵F・パリィ受付F・歩行速度を
      **実行時に計測して契約値と比較**し、誤差が ±5% 以内

      > 🧭 **「一致」を計測で確かめるのがこの条件の要点である。**
      > 契約の数字を信じて `audit` が検査し、`avatar` が別の値で動くと、
      > **公平性の保証が静かに壊れる。**（2026-09-04）

- [ ] **回答手段が4つとも機能する**:
      各手段が単独で、対応する技を無傷で抜けられる。
      判定: 形状ごとに台本入力を組み、宣言された手段で被弾0を確認

- [ ] **スタミナが枯れる**:
      **ローリングとパリィを連続で使い続けられない。**
      判定: 最速で回避入力を繰り返し、**10秒以内にスタミナ不足で行動が開始できなくなる**

- [ ] **交代が存在しない**:
      **キャラ配列・交代入力・自動交代のコードが1行も残っていない。**
      判定: `swap` / `aliveNext` / 3要素配列の grep が0件

- [ ] **空中制御を持たない**:
      **ジャンプ中の左右入力が横速度を変えない。**
      判定: 滞空中に方向入力を反転させ、着地点が変わらないこと

- [ ] **容量**: **3,400 inlined bytes 以内**（交代を削るぶん、実装より小さくなるはず）

## 5. 変えてはいけない前提

1. 根の不変条件12件。とくに **10**（反射神経に依存しない回答）
2. **回答手段は4つだけ。**増やさない
3. **資源はスタミナ1本。残機・控え・交代を作らない**
4. **X = 地上の移動軸 / Y = ジャンプ中のみの回避軸 / Z = 無し。空中制御を持たせない**
5. **危険範囲の矩形を作らない。**展開するのは `arena` だけ（`fight` の不変条件8）
6. **`foe` を直接読まない**（同 9）
7. **接触の解決順序**（`fight` の親に残すもの4）。`avatar` は無敵とパリィ受付の状態を
   `f1` で渡すだけで、**優先順の判断をしない**
8. **能力契約の値を ±25% で動かしたら、「宣言との一致」を再検査する**（`fight` の不変条件10）

## 6. 決めないこと・任せること

**実装が決めてよい**

- **プレイヤーの攻撃**（威力・リーチ・発生・全体フレーム・弾か近接か）。
  実装は3キャラぶんあるが、**1つを選ぶか作り直すかは実装の判断**
- スタミナの最大値・消費量・回復速度・停止時間（**公平性の検査に効かないので契約外**）
- 入力バッファのフレーム数（実装は 7 / 5）
- コヨーテタイムの長さ（実装は 6F）
- 被弾後無敵の長さ（実装は 42F）
- **`SHOT` を奪ったときの扱い**（プレイヤーの弾。実装の `shots` は既に `owner` を持つ）
- **`CHARGE` を奪ったときの扱い**（自分が前進する攻撃になる）
- キー割り当ての**値**（**ただし所有者は `avatar`。`s1.controls` で `read` へ運ぶ**。
  `read.frame.screens` が操作説明を生成する唯一の入力になる）
- 加速度・摩擦（実装は等速）

**今回は決めない**

- 回答手段を増やすこと
- プレイヤーの成長・装備

## 7. 分からないこと・仮置きしていること

1. **能力契約の値が実測とずれている。`boundary_request` を起票する。**

   ```md
   - from: duel.fight.avatar / date: 2026-09-04
     対象: duel の本文5 の 12（プレイヤー能力契約）の値
     理由: 契約は AI が直感で置いた provisional 値で、prismatic-duel/ の実測と
       突き合わせていない（duel-split-2「この提案自体への疑い」3 が自認）。
       実測は 内部解像度 640×360 / 当たり判定 12×25（半幅 6）/ 歩行 2.45 px/F /
       ジャンプ到達 59px。契約は 480×270 / 半幅 9・高さ 44 / 3.1 px/F / 52px。
       差が ±25% の調整幅を超えるため、avatar では直せない。
       ロール無敵 11F とパリィ受付 6F は一致している。
     status: open
   ```

   **起票先は `duel`。**`avatar` は親を書き換えない（`harness/README.md`）。
   **`audit` の検査 B は契約値を使うので、直るまで検査結果は暫定である。**

2. **交代を削ったあとの資源設計。**実装は控えの高速回復で交代に意味を持たせていた。
   1人になるとその軸が消え、**スタミナが「消費後30F 停止」だけの単純な資源になる。**
   仮置き: 根の 1.5 のまま「消費後しばらく回復が止まる」だけで層を作る。`provisional: true`。
   **足りなければ回復曲線（残量が少ないほど遅い等）を実装が足してよい**

3. **交代を削るとプレイヤーが弱くなる。**実質3残機が1残機になる。
   **`avatar` では調整できない** — 根の 1.8 は「難易度は敵側の危険度予算だけで上げる」と
   定めており、プレイヤー側を強くするのは方針違反である。
   `gen` 側の予算調整に委ねる。成立しなければ `boundary_request`

4. **プレイヤーの攻撃をどのキャラから採るか未定。**
   実装の3キャラは弾（UNICORN）/ 高火力近接（RED）/ 高速近接（BLUE）で性格が違う。
   **どれを1人にするかで戦闘の距離感が変わる。**6 へ委任したが、
   **`audit` の検査 B には影響しない**（回答手段の判定に攻撃は含まれない）
