## 親からの振り分け

- **責任**: 生成された技とセットが公平であるかを、副作用なしに判定する
- **詳細化の対象**: 親の本文1の機能「公平性を検査する」。`gen` の解決法5層のうち
  **3a（安全席の検査）3b（回答2つの検査）**
- **継承する制約**: 根12件＋`duel` 4件＋`gen` 3件。とくに
  **「公平性の保証は検査が持つ」「`audit` は副作用を持たない。技を書き換えない」
  「検査を通らない技は必ず捨てる」**。
  プレイヤー能力契約（`gen` の親に残すもの2）と形状の展開規則（同 3）。
  技の表現9要素（同 4）。**乱数を使わない**（同 5）。容量の目安 **2,600 inlined bytes**
- **割り当てられた受け入れ条件**: 公平性A（主）、公平性B（主）
- **uses_seams**: `g3.audit-request`
- **提供する seam**: `g4.audit-verdict`（`roster` へ）

## 1. これは何を決めるものか

**入力**（`g3.audit-request`）: 検査対象（技1つ、または技セット）＋ プレイヤー能力契約 ＋
座標系 ＋ **形状の展開規則**（`duel` の親に残すもの4。SHOT の 4.1 を含む）
**出力**（`g4.audit-verdict`）: 合否 / 違反の種別 /
**有効な回答手段の集合**（検査 B が数えた結果そのもの）/
**黄なら安全席テーブル**（**ボス中心 X からの相対オフセットと向きの組**）

> 🔒 **凍結（`audit@2026-09-06-decision-5`）。**
> 2026-09-05 の再監査（**重大5**）: 「`g3` は親で形状展開規則を運ぶが `audit` の入力に無い。
> `g4` は検査済み回答集合を返す必要があるが `audit` の出力は合否・違反・安全席だけ。」
> **親の seam 表と一致させた。**回答集合は検査 B が数えているので、そのまま返す。

**乱数を使わない。副作用を持たない。技を書き換えない。**
**同じ入力からは必ず同じ判定が出る**（根の不変条件9 が検査にも掛かる）。

### 1.1 3層の検査

| 層 | 対象 | 何を保証するか | 出所 |
| --- | --- | --- | --- |
| **A. 安全席** | **黄の技だけ** | 静止したまま避けられる位置が存在し、そこに座れる | 根の 1.3（`decision-6`） |
| **B. 回答が2つ** | **全技** | 有効な回答が2つ以上あり、うち1つは反射神経を要さない | 根の 1.4・不変条件10 |
| **C. セット条件** | **ボス1体の技セット** | 1体としての回答の多様性 | **実装の `validateBoss`**（30,000体 pass） |

**A と B は根の決定。C は実装から持ってきたもので、ツリーには無かった。**

### 1.2 A: 安全席（黄の技だけ）

**手順**

> 1. **危険包絡**を求める — 予備動作の開始から全段の攻撃判定が終了するまでに、
>    **ボスの移動・追尾・多段のすべてを含めて**、危険範囲が到達しうる X 区間の和集合
> 2. 包絡を**プレイヤーの半幅で膨張**させ、「禁止されるプレイヤー中心位置」の集合にする
> 3. 画面内の有効な中心位置から 2 を差し引いた残りが、**プレイヤー1人分以上の幅**を持つ
> 4. その席は**予備動作の開始時点で既に安全**であり、**攻撃の終了まで動かずに安全であり続ける**

**検査は全修飾子を合成したあとの技に対して行う。**個々の特性ではなく、
**出来上がった1つの技**が条件を満たすかを見る。

**黄を付けられない技**（根の 1.3・`decision-6`）:

- **危険形状の変換にプレイヤーの状態（位置・向き・速度）を使う技すべて。**
  発生位置だけでなく、**向き・軌道・オフセット**の決定に使う場合も含む
- **ボスの移動を伴う技**（予備動作中に踏み込む技）

**これを踏むと、安全席が「プレイヤーが今いない場所」として定義され、
選択時条件と原理的に両立しない。**

> ⚠️ **これらは実装（`prismatic-duel/`）に1行も無い。**
> 実装の危険範囲は `moveRect()` が**現在フレームの矩形1つ**を返すだけで、
> **時系列の和集合を取る仕組みが無い。**`audit` の A は**新規に書く部分**である。

### 1.3 B: 回答が2つ（全技）

**能力契約と親の形状展開規則から、時空間の到達可能性を保守的に評価する。**

> 🔒 **凍結（`audit@2026-09-04-decision-2`）。旧文はフラグと大小比較を数えるだけだった。**
>
> 2026-09-04 の Codex 監査（**着手前3**）:
> **「移動量・`無敵F ≥ 持続F`・フラグ有無を個別に数えるだけで、
> 開始位置・回避開始時刻・ロール移動距離・多段・弾道を再現しない。
> 必要条件を通っただけの攻撃を『有効回答』に数えるので、
> 根の不変条件10 に対して偽陽性がある。」**
>
> **保守的（= 通ったら本当に回避できる）な形へ直した。**
> 判定に使うのは `duel` の親に残すもの4 の**展開規則そのもの**で、
> `fight.arena` が実戦で使うのと**同じ規則**である。
> **`audit` と `arena` が同じ純関数を共有する**ので、検査と実戦が食い違わない。

**判定は「初期位置の区分ごとに1つ以上、技全体で2種類以上」で行う。**

> 🔒 **凍結（`audit@2026-09-06-decision-5`）。旧文は「すべての X 位置から避けられる」だった。**
>
> 2026-09-05 の3回目の監査（**重大2**）: 「**THRUST の包絡内から開始すると
> 移動経路が最初から包絡に触れ、ジャンプ不可、残るロール・パリィは両方反射回答。
> したがって『非反射回答を1つ含む2回答』を常時満たせない。」**
>
> **指摘は成立するが、原因は旧文の定義が根の 1.4 を読み違えていたことである。**
> 根の 1.4 は「**すべての生成攻撃は、最低2種類の有効な対処を持つ**」と書いており、
> **「どんな初期位置からでも2種類ある」とは言っていない。**
> 包絡の内側に自分から入った状態で「離れて避ける」が使えないのは、
> **理不尽ではなく位置取りの結果である。**

| 初期位置の区分 | 要求 |
| --- | --- |
| **包絡の外**（予備動作の開始時点で危険範囲に触れていない） | **その区分の全 X 位置から、反射神経を要さない回答が1つ以上**（その場に留まる / 早めに離れる / ジャンプで越える） |
| **包絡の内**（自分から踏み込んでいる） | **その区分の全 X 位置から、回答が1つ以上**（ロール / パリィ / ジャンプ を含む） |
| **技全体** | **有効な回答が2種類以上**あり、そのうち**1つ以上が反射神経を要さない** |

> 🔒 **量化は「区分内の全 X 位置から」である**（`audit@2026-09-06-decision-5`）。
> 2026-09-06 の4回目の監査: 「**各区分の全 X なのか、区分内のどこか1点で存在すればよいのか
> 未定義。後者なら回答不能な開始位置からも技が選択でき、不変条件10 の実効性に穴が残る。」**
>
> **全 X を採る。**「どこか1点で避けられる」では、
> **踏み込んだプレイヤーが必ず死ぬ位置**が残りうる。

**「包絡の外に安全な位置が1つも無い技」は不合格。**（これは検査 A と別で、A は黄だけ・
静止維持まで要求する。B は全技・区分ごとの存在だけを見る）

| 回答手段 | 有効と判定する条件 | 反射神経 |
| --- | --- | --- |
| **早めの移動 / 距離を取る** | 予備動作の開始位置から、`歩行速度 × 予備動作長` の範囲内に、**攻撃の全段が終わるまで危険包絡に触れない X 区間**がある。**移動中の経路も包絡に触れないこと** | **要らない** |
| **ジャンプで越える** | 各段の危険範囲の**上端が、ジャンプの高度曲線の下**に収まる時刻があり、**滞空35F の中で全段を跨げる。**着地点が包絡の外である | **要らない** |
| **ローリングで抜ける** | 無敵 11F（全体24F の 4〜14F）を**当てられる時刻**があり、**その間に全段の判定が収まる。**ロール移動 110〜139px 後の位置が包絡の外である | 要る |
| **パリィする** | `m[F] & PARRY` が立ち、**受付 6F（全体22F の 4〜9F）を各段に当てられる。**多段なら**段間隔がパリィ全体22F より長い**（連続で受け直せる） | 要る |

**判定**: 有効な回答が**2つ以上**あり、そのうち**1つ以上が「反射神経を要求しない」**。

**多段・追尾・ボスの移動をすべて含めて評価する。**危険包絡（1.2）と同じ時系列を使う。

> 🧭 **「保守的」とは、判定が偽陽性を出さないという意味である。**
> 偽陰性（本当は避けられるのに不合格）は許す — **捨てて引き直せばいいだけ**で、
> 根の不変条件10 は破れない。逆は破れる。（2026-09-04）

> 🧭 **「反射神経を要求しない」の線引きは、根の 1.4 の2分類をそのまま使う。**
> ロールとパリィは「難しいが反撃しやすい方法」の側で、**これだけでは条件を満たさない。**
> 安全席（A）は「早めの移動 / 距離を取る」1つしか証明しないので、
> **A を通っても B を通るとは限らない。**逆も同じ。（2026-09-04）

### 1.4 C: セット条件（ボス1体の技セット）

**実装が既に持っている保証。**技1つずつではなく、セット全体に課す。

| 条件 | 落ちる基準 |
| --- | --- |
| 技数 | 1体目4技 / 2・3体目5技でない |
| **ジャンプ回答** | `JUMPABLE` の技が**0個** |
| **パリィ回答** | `PARRY` の技が**2個未満** |
| 遠距離への圧力 | 射程4 も突進も無い |
| **反撃窓** | 硬直 ≥50F の技が**2個未満** |
| 高速技 | 24F 技が**2個以上** |
| 帯域 | 危険度が `limits` の外。**ただし攻撃後硬直が 50F 以上（`C ≥ 3`）の技は、下限を 2 下げて判定する** |
| 数値健全性 | NaN / Infinity |

> 🔒 **帯域の下限に例外がある**（`audit@2026-09-06-decision-5`）。
> 2026-09-05 の3回目の監査（**実装の検証・技別帯域**）: 「**実装は長硬直なら下限を2下げる
> 独自例外を持つ**（`validateBoss`）**が、`audit` C は例外なしと書いている。**
> 追加走査では、合計上限の削減処理だけで通常帯域割れが **tier1 で 7,263技、tier2 で 3,375技**
> 新たに発生した。」
>
> **実装の側が正しい。**硬直を延ばして反撃時間を返した技は、
> 危険度が下がっても**プレイヤーにとって弱すぎる技にはならない**（反撃機会が増えるだけ）。
> `roster` の後処理（反撃窓の確保・合計上限の削減）は硬直を延ばす方向に働くので、
> **例外が無いとその後処理自体が帯域違反を生む。**設計を実装へ合わせた。

**出所は実装**（`validateBoss`）。[`design/AS_BUILT.md`](../../../../AS_BUILT.md) §5。
**10,000 シード × 3 tier = 30,000体で通っている。**

> 🧭 **C を捨てないのが `audit` の設計判断である。**
> A と B は「技1つが公平か」しか見ない。C は「**1体として回答が偏っていないか**」を見る。
> たとえば全技がパリィ専用でも A・B は通るが、**ジャンプが一度も要らないボス**になる。
> 根の 1.4 が回答手段を4つ挙げている以上、**セットとしての多様性は別の命題である。**
> （2026-09-04）

### 1.5 判定の粒度

| `g3` の要求 | `g4` で返すもの |
| --- | --- |
| 技1つ | A（黄なら）・B の合否。黄なら安全席テーブル |
| 技セット | C の合否と、違反した条件の一覧 |

**`roster` は技単位で引き直し、セット単位で組み直す。**
どちらの引き直しも `roster` の内部で完結する（`gen` の分割の要点）。

## 2. なぜ要るのか

**列挙では塞ぎきれない。**根の 1.3 は当初「短い予備動作 × 長射程」1つだけを禁止していたが、
Codex の前検査3回で **黄×藍・黄×紫・接近後攻撃・一度だけ照準を合わせる技・
安全席が排他的な組**が次々に見つかった。**禁止を足すたびに新しい抜け道が出た。**

**そこで保証を検査へ移した。**禁止の列挙は `move` の `harden` に残っているが、
**あれは引き直しを減らす最適化であって保証ではない**（`gen` の不変条件3）。

**`audit` が副作用を持たないのは、この保証を守るためである。**
検査と「検査を緩める権限」が同じノードにあると、
不合格を「基準を下げて合格」に変えられてしまう。

## 3. 誰が使い、誰が影響を受けるか

- **`roster`**: `audit` を呼ぶ唯一の相手。不合格なら**捨てて引き直す**実行責任を持つ
- **`fight`**（親経由）: 安全席テーブルを `d1` で受け取り、**選択時条件の判定に使う。
  再計算しない**
- **`move`**: `audit` を知らない。判定は `move` の都合と無関係に下される
- **プレイヤー**: ここが漏れると「理不尽だった」としか言えない敗北が生まれ、
  受け入れ条件「初見」が壊れる。**しかも特定のシードでしか出ない**

## 4. 終わったとどうやって分かるか（受け入れ条件）

- [ ] **公平性 A（安全席）**: 10,000 シードで生成した**黄の技すべて**が
      1.2 の4条件を満たす。違反0件

- [ ] **公平性 B（回答が2つ）**: 同じ 10,000 シードで**すべての技**が
      1.3 の判定を満たす。違反0件

- [ ] **セット条件 C**: 同じ 10,000 シードで 1.4 の8条件すべてに違反0件。
      **実装済みの `test.mjs` がこれを既に行っている**（30,000体 pass）

- [ ] **決定論**: 同じ入力に対して**必ず同じ判定**が出る。
      判定: 全検査を2回ずつ走らせ、合否と安全席テーブルがバイト一致。
      **浮動小数の丸めに依存しない形で判定していること**（`duel` の不変条件・決定論の規約）

- [ ] **副作用なし**: 検査の前後で**入力の技が1バイトも変わらない。**
      判定: 検査前後で技をシリアライズして比較。10,000 回で全一致

- [ ] **偽陰性を出さない**（手で作った不公平な技を落とせる）:
      **既知の抜け道5つ**（黄×藍 / 黄×紫 / 接近後攻撃 / 一度だけ照準を合わせる技 /
      安全席が排他的な組）を**手で作って入力し、全件を不合格にできる**。
      判定: 回帰テストとして固定する

      > 🧭 **これが一番大事な条件である。**「10,000 シードで違反0件」は、
      > **検査が何も見ていなくても通る。**落とせることを別に確かめないと意味がない。（2026-09-04）

- [ ] **容量**: **2,600 inlined bytes 以内**

## 5. 変えてはいけない前提

1. 根の不変条件12件。とくに **10**（すべての生成攻撃は反射神経に依存しない回答を最低1つ持つ）
2. `duel` の不変条件4件。とくに**プレイヤー能力契約**と**決定論の規約**
3. `gen` の不変条件3件。とくに
   - **副作用を持たない。技を書き換えない**（`gen` の不変条件9）
   - **乱数を使わない**（同 10）
4. **形状の展開規則は `duel` のもの**（`gen` の親に残すもの3）。
   `audit` は展開して包絡を計算するが、**規則そのものを書き換えられない**
5. **検査を通らない技は必ず捨てる。**「ほぼ安全」で通さない（`duel` の不変条件11）
6. **A の対象は黄の技だけ。**根の 1.3 の範囲を広げない

   > ⚠️ **`duel@2026-09-03-decision-1` はここを全技へ広げていて、失効した**
   > （Codex `duel-split-1` 前検査 重大6）。
   > 全技に静止安全席を要求すると、**移動して避ける技・ジャンプで越える技・
   > ロールで抜ける技が1つも生成できなくなる。**同じ誤りを繰り返さないこと

## 6. 決めないこと・任せること

**実装が決めてよい**

- **危険包絡の計算方法**（区間演算か、フレーム単位の離散サンプリングか）。
  ただし**決定論であること**と**浮動小数の丸めに依存しないこと**は前提
