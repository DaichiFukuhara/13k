## 1. これは何を決めるものか

**入力**: シード（32bit 整数）1つだけ
**出力**: `d1.run-definition` — ラン全体を最後まで走らせるために必要な確定済み定義すべて

**`roster` は `gen` の3子で唯一、状態と乱数系列を持つ。**

### 1.1 ラン全体を一度に作る

```
シード ──► ボス0（tier 0）──┐
      ──► ボス1（tier 1）──┼──► d1.run-definition ──► fight
      ──► ボス2（tier 2）──┘
```

**1体ずつではない。**`fight` が「次を作れ」と言う必要が無くなり、
**`fight → gen` の逆向きが原理的に生まれない**（`duel-split-2` の変更1）。

**成立する理由は根の 1.8 にある** — 「難易度は**敵側の危険度予算だけ**で上げる
（プレイヤー側の成長で上げない）」。
**N 体目の予算はシードとボス番号だけで決まり、戦績に依存しない。**
`fight` の結果を待つ理由がそもそも無い。

### 1.2 ボス1体を組み立てる手順（8段）

| # | 段 | 中身 |
| --- | --- | --- |
| 1 | **乱数列を作る** | シードとボス番号から専用の系列を導出する。**これ1本だけを使う** |
| 2 | **役割枠を決める** | `[突き, 横薙ぎ, 接近/遠距離, 範囲制圧, 固有技]`（1体目は4枠） |
| 3 | **各枠を数値化** | `g1` で `move` へ要求し、`g2` で受ける |
| 4 | **検査へ出す** | `g3` で `audit` へ。**不合格なら捨てて 3 からやり直す（最大8回）** |
| 5 | **上限超過ならフォールバック** | 検査を必ず通る**固定の技**（1.2.1）を採用 |
| 5b | **フォールバックを必ず1つ載せる** | 引き直しが起きなかったボスにも、**`d1` の予備枠として同じ固定技を付ける**（下記） |
| 6 | **セットの後処理** | GAP 枠の圧力・反撃窓の確保・高速技の抑制。**そのつど再検査する** |
| 7 | **外見を決める** | **特性ごとの危険度加点を全技で合計し、最大の特性の色を主色にする**（根の 1.6・`root@2026-09-04-decision-8` で凍結）。**乱数で選ばない** |
| 8 | **HP・体勢・山札の材料を付ける** | `tier` ごとの値 |

### 1.2.1 フォールバック技（具体値で固定）

> 🔒 **凍結（`roster@2026-09-05-decision-3`）。**
> 2026-09-04 Codex 監査 **P0-3**: 「`1.2.1 で具体値を凍結` と参照するが、**同ファイルに 1.2.1 は無く、
> 9パラメータの固定値も無い。**具体値は `design/README.md` の要約にしかなく、**要約は正本ではない。**
> この状態では『必ず検査を通る固定フォールバック』による**停止証明が成立しない。」**

| 添字 | 項目 | 値 | 理由 |
| --- | --- | ---: | --- |
| `S` | 形状 | **1（THRUST）** | ボスの移動を伴わず、包絡が最も素直。多段も追尾も付かない |
| `D` | 威力 | **3** | 帯域の下限を満たすために要る（`DMG_COST[3] = 6`） |
| `R` | 射程 | **1**（48 px） | 最小。包絡が 48 px に収まり、移動で抜けられる |
| `W` | 予備動作 | **3**（54 F） | **黄にならない**（黄は `W ≤ 2`）かつ、80F より加点が高い |
| `A` | 持続 | **1**（5 F） | 最小 |
| `C` | 攻撃後硬直 | **2**（32 F） | 反撃窓は確保しつつ、減点を −1 に抑える |
| `T` | 追尾 | **0** | 無し |
| `N` | 多段 | **1** | 単発 |
| `F` | 宣言 | **移動 ＋ パリィ** | THRUST の規定どおり（`duel` の展開規則） |

**危険度**: `DMG_COST[3] + RANGE_COST[1] + WIND_COST[3] + REC_COST[2] = 6 + 0 + 0 − 1 = 5`。

| `tier` | 通常技の帯域 | 5 は入るか |
| ---: | --- | --- |
| 0 | `[3, 6]` | ✅ |
| 1 | `[4, 7]` | ✅ |
| 2 | `[5, 8]` | ✅ |

**3体すべての帯域に入る。**固有技の帯域（`[6+tier, 8+tier×2]`）には入らないので、
**固有技枠がフォールバックへ落ちた場合も、通常技として置く**（1.2.1 の末尾）。

> 🔒 **凍結（`roster@2026-09-05-decision-3`）。**
> 2026-09-05 の再監査（**重大2**）: 「初稿の固定技は危険度 **−6** で帯域下限未満。
> **『フォールバックは帯域検査の対象外』と自己宣言しているが、
> `audit` の C は『帯域: 危険度が limits の外』を無条件の不合格条件に挙げている。**
> しかも `roster` は `audit` の合否を上書きしてはならない（本文5-5）。
> **解釈の余地がない直接矛盾。」**
>
> **例外を作るのではなく、帯域に入る値へ変えた。**
> 威力を 3、予備動作を 54F、硬直を 32F にすると危険度が 5 になり、**3 tier すべての帯域に入る。**
> **`audit` に例外規定を置かない**ので、「検査を通らない技は必ず捨てる」（`duel` 不変条件11）が
> フォールバックにもそのまま掛かる。

**有効な回答集合**（能力契約に対する検査 B の結果）

| 回答 | 成立の根拠 | 反射神経 |
| --- | --- | --- |
| **早めの移動 / 距離を取る** | 予備動作 54F × 歩行 2.45 px/F = **132 px 動ける。**包絡は 48 px（THRUST は**ボスが動かない**ので包絡＝射程） | **要らない** |
| **ローリングで抜ける** | 無敵 11F > 持続 5F。単発なので当てる時刻が1つだけ | 要る |
| **パリィする** | `PARRY` が立ち、受付 6F > 持続 5F | 要る |

**回答は3つ。うち1つは反射神経を要さない。**

> ⚠️ **これは「必ず通る」の証明ではない。**
> `audit B` は「**全初期 X 位置**から」「**移動中の経路も包絡に触れない**」を要求する
> （`audit` 1.3）。上の 132 px は代表値であって、**画面端に貼りついた初期位置での検証ではない。**
> **受け入れ条件の回帰試験で実測する**（4 の「フォールバックが検査を通る」）。
> **落ちたら値を変える** — 例外を作らない。

**安全席の要否**: **不要。**`W = 3`（54F）なので黄（`W ≤ 2`）ではなく、**検査 A の対象外**である。

**第2形態での扱い**: **変異しない。**第2形態が変異させるのは**固有技だけ**であり、
フォールバックは固有技枠に入らない（固有技が引き直し上限を超えた場合も、
**フォールバックは固有技の性質を持たない通常技として置く**）。

**セット条件（検査 C）への影響**: フォールバックは `JUMPABLE` を持たないので、
**ジャンプ回答の1件としては数えない。**`roster` は
**フォールバックを採用した後、必ずセット条件を再検査する**（1.3 の後処理と同じ扱い）。

#### フォールバックは全ボスが持つ（`d1` の予備枠）

> 🔒 **凍結（`roster@2026-09-05-decision-3`）。**
> 2026-09-05 の3回目の監査（**重大3・未解消**）: 「`foe` の段5 は『`d1` のフォールバックを出す』
> とするが、**`roster` は引き直し上限超過時にだけ採用している。
> 全技が8回以内に通ったボスはフォールバックを持たない。**
> `d1` のフィールドにも常設フォールバックが無く、
> **参照する値が存在しないので停止証明が成立しない。」**
>
> **指摘は成立する。**`foe` の停止性を `d1` の中身に依存させたのに、
> **その中身が常にあることを保証していなかった。**
>
> **全ボスが 1.2.1 の固定技を「予備枠」として持つ。**技リストとは別枠で、
> **山札には入らない**（通常の選択では出ない）。`foe` の段5 でだけ使う。
> **技数の検査（C の「1体目4技 / 2・3体目5技」）には数えない。**

> ⚠️ **「必ず通る」は実測で確かめる。**上の根拠は能力契約の値からの計算だが、
> **`audit` の実装が保守的に判定した結果と一致する保証は無い。**
> 受け入れ条件に回帰試験として入れた（4 の「フォールバックが検査を通る」）。

### 1.6 決定論の規約

- 乱数は**シードから導出した1本の系列**だけ。時刻・端末・実行回数に依存しない
- **引き直しは乱数の状態を進める。**それも含めてシードから再現できる
- **見た目の乱数（火花・画面揺れ）とは別系統。**
  実装は生成に `seeded()`（Mulberry32）、演出に `Math.random()` を使い分けている。
  **見た目の乱数を何回呼んでも次のリトライのボス構成は変わらない**
- **リトライ時は生成をやり直さない。**`fight` が `d1` を保持する（`fight` の責任）

## 2. なぜ要るのか

**引き直しのループを、どこかが持たなければならない。**
`move` に持たせると生成器が自分の検査結果を見ることになり、
`audit` に持たせると検査器が技を書き換えることになる（`gen` の不変条件9 違反）。

**`roster` をハブにすると、`move` と `audit` の間に線が1本も無くなる。**
親（`duel`）が5子案を却下した理由（検査器と生成器の間に引き直しのループが通る）は、
これで消える。

**停止性もここが持つ。**上限8回とフォールバックが無いと、
**特定のシードで生成が終わらない可能性がある。**

## 3. 誰が使い、誰が影響を受けるか

- **`fight`**: `d1.run-definition` を受け取る唯一の相手
- **`move` / `audit`**: `roster` から呼ばれるだけ。互いを知らない
- **`read`**（親経由）: 外見（主色・武器シルエット・緑の輪郭）は `roster` が決める。
  根の 1.1「姿から性格を推測する」がここに乗っている
- **プレイヤー**: 生成の待ち時間を体感する

## 4. 終わったとどうやって分かるか（受け入れ条件）

- [ ] **決定論**: 同一シードから2回作った**ラン全体**がバイト一致する。
      判定: 1,000 シードで2回ずつ生成し、シリアライズして全一致。
      **実装済みの `test.mjs` が同じことを1体単位で行っている**（30,000体 pass）

- [ ] **停止性**: どのシードでも有限時間で終わる。
      判定: **構造上の根拠**（引き直し上限8回＋必ず通る固定フォールバック）をコードで確認し、
      10,000 シードで無限ループ・例外0件。**引き直しが8回を超えた場合に
      フォールバック技が採用されていること**を記録して確認

- [ ] **公平性の実行責任**: `audit` が不合格にした技が、**1つも出力に残っていない。**
      判定: 出力された全技を `audit` へ再投入し、**全件合格**であること。
      これは A・B の判定そのものではなく、**「捨てる」が実行されたか**の検査である

- [ ] **形状と外見の網羅**: 10,000 シードで**全6形状**と**全4防御状態**が出現し、
      外見（色 × 武器）が **20種類以上**出る。
      判定: `test.mjs` の既存検査（現状 6 / 4 / 21 で pass）

- [ ] **後処理後の再検査**: セットの後処理で技を書き換えたあと、
      **必ず `audit` へ出し直している。**
      判定: 後処理を通った全技が出力後の再投入で合格（上と同じ検査でカバーされる）

- [ ] **フォールバックが検査を通る**（停止性の証明の土台・**回帰試験**）:
      **1.2.1 の9パラメータをそのまま `audit` の A・B・C へ入れて、全件合格する。**
      判定: 固定値として回帰試験に入れる。
      **`audit` の実装を変えたとき、ここが落ちたら停止性の証明が崩れる**ので必ず検出する。

      > 🧭 **停止性は「引き直し上限8回 ＋ 必ず通る固定技」で証明する。**
      > 後半が実測で確かめられていないと、**証明が仮定の上に乗る。**（2026-09-05）

- [ ] **容量**: **1,700 inlined bytes 以内**

## 5. 変えてはいけない前提

1. 根の不変条件12件。とくに **9**（同じシードは同じ敵を再現する）
2. `duel` の不変条件4件。とくに**決定論の規約**
3. `gen` の不変条件3件。とくに
   - **乱数系列を持つのは `roster` だけ**
   - **フォールバック技は検査を必ず通る固定値。生成しない**
4. **検査を通らない技は必ず捨てる。**「ほぼ安全」で通さない（`duel` の不変条件11）
5. **`audit` の判定を上書きしない。**`roster` は捨てるか採るかを決めるだけで、
   **合否そのものを変えられない**
6. **ラン全体を1つのシードから決める**（`gen` の親に残すもの）。1体ずつにしない

## 6. 決めないこと・任せること

**実装が決めてよい**

- 引き直し上限の値（8 は根の 1.3 の値。据え置きを推奨）
- 乱数の導出方法（実装は `seed ^ imul(tier+1, 0x9e3779b9)`）
- 役割枠の並び（実装は `[突き, 横薙ぎ, 接近/遠距離, 範囲制圧, 固有技]`）
- 山札の並べ方の材料をどう渡すか（実装は周回ごとにシャッフルするので、材料はシードだけ）
- 第2形態変異の中身（実装は固有技の威力・予備動作・硬直を +1）
- HP・体勢の値（実装は `[120,160,210]` / `[24,32,42]`）

**今回は決めない**

- ボスの体数を3から変えること（7-1 の仮置き。変えるなら `boundary_request`）
- 1体ずつ生成へ戻すこと（`fight → gen` の輪が復活する）

## 7. 分からないこと・仮置きしていること

1. **ボス何体で1ランか。**根の 1.8 は仮置きのまま、根の 6 から `duel` へ委任された。
   **仮置き: 3体**（実装が既に3体で動いている）。`provisional: true`。
   変えるなら `roster` では決められないので `boundary_request` で `gen` へ上げる

2. **後処理で不合格へ落ちたときの扱いが未定。**
   実装は後処理のあとに `validateBoss` を通すだけだが、
   **A（安全席）と B（回答2つ）が入ると、後処理が技を悪化させうる。**
   仮置き: 後処理も引き直しの対象に含め、**8回の上限を共有する**。
   超えたらその技をフォールバックへ置き換える

3. **ラン全体を持つと容量を食う。**3体 × 5技 × 安全席テーブルを同時に持つ。
   1,700 bytes は**組み立てのコードだけ**の見積もりで、**データの大きさは別**である。
   `d1` の実サイズを見積もっていない

4. **生成の待ち時間が1回に集中する。**ラン全体を作るので、
   最悪ケースは「3体 × 5技 × 引き直し8回 × 検査」になる。
   仮置き: タイトル画面で隠す。**実測していない**

5. **`audit` に A・B が入ると、引き直し率が上がる可能性がある。**
   実装の `validateBoss`（C だけ）は 30,000体で1件も落ちていないが、
   A・B は一度も動いていない。**落ちる率が高いと停止性に効く**
