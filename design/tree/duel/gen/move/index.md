## 1. これは何を決めるものか

**入力**（`g1.move-request`）: 形状枠 / `tier`（0〜2）/ 固有技か / **乱数の値列**
**出力**（`g2.move-result`）: 技1つ（9要素の配列）/ 危険度 /
**特性ごとの加点の内訳** / **消費した乱数の個数**

> 🔒 **凍結（`move@2026-09-05-decision-2`）。**
> 2026-09-04 Codex 監査 **P0-6**: 「`gen` の現行 `g1` / `g2` は『乱数の値列』と
> 『特性別加点＋消費個数』を定義するが、**`move` は乱数関数を受け、技＋危険度だけを返す。」**
> **親の seam 表と子の入出力が食い違っていた。**親に合わせた。
>
> | なぜ値列か | なぜ内訳か | なぜ消費個数か |
> | --- | --- | --- |
> | **乱数系列を持つのは `roster` だけ**（`gen` の不変条件10）。関数を渡すと `move` が状態を進める | **主色は寄与の合計が最大の特性**（根の 1.6）。`roster` が合計するには内訳が要る | `roster` が**次に何個引けばよいか**を知るため。決定論の再現に要る |
>
> **足りなくなった場合**: `move` は**値列の長さを超えて引かない。**
> 足りなければ `g2` で不足を返し、`roster` が引き直す。
> **`move` が乱数を作ることは無い。**

**副作用を持たない。**同じ入力と同じ値列からは、必ず同じ技が出る。

### 1.1 手順（6段）

1. **形状ごとの許可射程**から1つ選ぶ
2. **威力・予備動作・持続・硬直**を段階値で抽選する
3. **弾と落下攻撃だけ**追尾を抽選する
4. **固有技だけ**多段と長時間持続を抽選する
5. 形状から**有効な回避フラグ（宣言）**を決める
6. **禁止組み合わせを崩し、帯域へ収める**（`harden` → `balance`）

**フレーム数を直接ランダムにしない。**段階値を変換表で実フレームへ写すので、
24 / 36 / 54 / 80F という**読みやすいリズムだけが生成される。**

### 1.2 危険度（`threat`）

```
危険度 = 威力コスト + 射程コスト + 予備動作コスト + 硬直コスト
       + 追尾×2 + (段数−1)×2 + (持続が最大なら +2)
```

| 軸 | 段階1 | 2 | 3 | 4 |
| --- | ---: | ---: | ---: | ---: |
| **威力**（加点） | 1 | 3 | 6 | 9 |
| **射程**（加点） | 0 | 1 | 3 | 5 |
| **予備動作**（加点/減点） | **+4** | +2 | 0 | **−2** |
| **攻撃後硬直**（減点） | 0 | −1 | −3 | −5 |

**根の 1.3「特性と代償は別の軸」が、加点と減点として実装される。**
予備動作は1軸なので、**「短い予備動作の代償が長い予備動作」という矛盾は原理的に起きない。**

**威力が線形でない**（1/3/6/9）のは、高威力どうしの組み合わせを重く扱うためである。

### 1.3 帯域（`limits`）

```
通常技 = [3 + tier,  6 + tier]
固有技 = [6 + tier,  8 + tier×2]
```

> ⚠️ **根の共通語彙とずれている。**根は 危険度予算 を「**ボス1体が持てる**危険度の範囲」と
> 定義しているが、これは「**技1つが収まる帯域**」である（`AS_BUILT.md` §8 の差分5）。
> **7-1 で扱う。**

### 1.4 禁止組み合わせ（`harden`）— 予算とは別に、無条件で崩す

`balance` の反復中にも毎回呼ぶので、**数値調整で禁止構成へ戻れない。**

| 条件 | 強制する内容 |
| --- | --- |
| 予備動作が最速（24F） | 威力 ≤2 / 追尾 ≤1 / **単発のみ** |
| 威力4 かつ 射程4 | 予備動作 ≥54F / 硬直 ≥50F |
| 射程4 かつ 追尾2 | 威力 ≤2 / 予備動作 ≥36F |
| 3段攻撃 | 1段の威力を **1 に固定** |
| 持続が最大 かつ 追尾2 | 追尾を1へ下げる |

**根の 1.3 が「引き直しを減らすための最適化」と位置づけたものがこれである。**
**保証ではない。**保証は `audit` が持つ（`gen` の不変条件3）。

### 1.5 帯域へ寄せる（`balance`）— 反復は最大24回

| 状況 | 直す順序 |
| --- | --- |
| **強すぎる** | 硬直を延ばす → 予備動作を延ばす → 追尾 → 多段 → 威力 → 射程 |
| **弱すぎる** | 硬直を縮める → 予備動作を縮める → 威力 → 射程 |

**攻撃の個性を消す前に、プレイヤーへ反撃時間を返す方向で調整する。**
24回で打ち切るので、**バグがあってもブラウザを固まらせない**（受け入れ条件「停止性」）。

### 1.6 形状6種と許可射程・宣言

| 形状 | 許可射程 | 宣言される回答（`m[F]`） |
| --- | --- | --- |
| 0 SWEEP（横薙ぎ） | 2〜3 | 移動 / **ジャンプ** / パリィ |
| 1 THRUST（突き） | 1〜3 | 移動 / パリィ |
| 2 SLAM（叩きつけ） | 1〜2 | 移動 |
| 3 CHARGE（突進） | 3〜4 | 移動 / **ジャンプ** / パリィ |
| 4 SHOT（弾） | 3〜4 | 移動（弾はパリィで**反射**できる） |
| 5 RAIN（落下攻撃） | 3〜4 | 移動 |

- **追尾を抽選するのは SHOT と RAIN だけ**（`shape === 4 || shape === 5`）
- **多段と長時間持続は固有技だけ**
- **威力の上限が `tier` で上がる**（`1 + rand(min(4, 2 + tier + 固有技))`）

**出所は実装**（`prismatic-duel/game.js` の `makeMove` / `threat` / `harden` / `balance` /
`limits`）。[`design/AS_BUILT.md`](../../../../AS_BUILT.md) §3・§4。
**30,000体のテストを通っている。**

## 2. なぜ要るのか

技の生成を独立させないと、**「検査を通らない技を、検査を緩めて通す」直し方ができてしまう。**
`move` を副作用の無い純関数にすると、`audit` の判定は
**`move` の都合と無関係に**下される（`gen` の不変条件9）。

また `move` は**乱数系列を持たない。**乱数関数を `g1` で受け取るだけである。
2箇所から乱数を引くと、根の不変条件9（同じシードは同じ敵）が壊れる。

## 3. 誰が使い、誰が影響を受けるか

- **`roster`**: `move` を呼ぶ唯一の相手。引き直しのたびに呼び直す
- **`audit`**: `move` の出力を検査するが、**`move` を知らない。**技の表現だけを見る
- **`read`**（親経由）: 特性ベクトルと主色の材料は `move` が決めた数値から来る
- **実装者**: 変換表（`REACH` / `WIND` / `ACTIVE` / `REC`）を触ると、**全ボスの手触りが変わる**

## 4. 終わったとどうやって分かるか（受け入れ条件）

- [ ] **決定論**: 同じ入力と同じ乱数列から、**同じ9要素が出る**。
      判定: 乱数関数をシード固定で再生成し、10,000 回の呼び出しで全一致

- [ ] **停止性**: `balance` の反復が**必ず24回以内で終わる**。
      判定: 反復回数を計測し、10,000 回の生成で上限超過0件。
      **加えて、24回で帯域へ収まらなかった場合の出力も有効な技であること**
      （帯域外でも `harden` は通っている）

- [ ] **禁止組み合わせが残らない**: 出力が `harden` の5条件を**すべて満たす**。
      判定: 10,000 回の生成で違反0件。**実装済みの `validateBoss` が同じ検査を持つ**

- [ ] **形状の網羅**: 10,000 シードの生成で**6形状すべて**が出現する。
      判定: `test.mjs` の既存検査（現状 pass）

- [ ] **宣言が形状と一致する**: `m[F]` が 1.6 の表どおりである。
      判定: 全出力で形状 → フラグの写像が表と一致

- [ ] **容量**: **2,300 inlined bytes 以内**

## 5. 変えてはいけない前提

1. 根の不変条件12件。とくに **9**（同じシードは同じ敵）
2. `duel` の不変条件4件。とくに**プレイヤー能力契約**（形状の寸法を決めるときに使う）
3. `gen` の不変条件3件。とくに
   - **乱数系列を持たない。**渡された関数だけを使う
   - **予算と禁止列挙は最適化にすぎない。**「帯域に収まっているから安全」と論じてはいけない
4. **技の表現は9要素の配列**（`gen` の親に残すもの4）。増やさない
5. **形状の展開規則は `duel` のもの。**`move` はパラメータを作るだけで、矩形を作らない
6. **副作用を持たない。**入力を書き換えない

## 6. 決めないこと・任せること

**実装が決めてよい**

- 変換表の**具体的な数値**（`REACH=[48,82,136,250]` / `WIND=[24,36,54,80]` /
  `ACTIVE=[5,8,12]` / `REC=[18,32,50,76]`）。**据え置きを推奨するが、
  プレイテストで動かしてよい。**ただし `WIND[0]` は知覚の下限 18F を下回らないこと
- コスト表の具体的な数値
- 抽選の書き方（配列の添字か、条件分岐か）
- `balance` の反復上限（24 は実装値。減らしてもよい）

**今回は決めない**

- 形状を増やすこと（6種は `gen` の親に残すもの4 の変換表に含まれる）
- 技の表現を9要素から変えること

## 7. 分からないこと・仮置きしていること

1. ~~危険度予算の定義がツリーと実装でずれている~~ → **解消**（2026-09-04）。
   **根が 1.3 で2層に定義し直した**（`root@2026-09-04-decision-8`）ので、
   `move` は**技の帯域**を持ち、**ボスの合計上限は `roster` が持つ。**
   旧文は「実装のまま技ごとの帯を採る」と `boundary_request` 無しに決めており、
   Codex 監査の**着手前8**で「**子による祖先決定の再選択**」と指摘された。
   以下は当時の記録である。

   **仮置き: 実装のまま「技1つの帯域」を採る。**`provisional: true`。理由は2つ。
   - **合計上限を課すと、`roster` の引き直しが増える**（1技を直すと合計が動く）
   - **実装が 30,000体で通っている**のに対し、合計上限版は一度も動いていない

   **根の共通語彙を変えるなら `boundary_request` が要る。**
   `move` は根を書き換えられないので、**ここに記録して `gen` へ上げる**

2. **`balance` が24回で収まらなかった場合の出力を、`audit` がどう扱うか未定。**
   帯域外だが `harden` は通っている技になる。
   仮置き: `roster` が引き直す対象にする（`audit` は帯域も見る）

3. **能力契約を形状の寸法決定にどう使うか未定。**
   実装の `REACH` は固定値で、プレイヤーの半幅と無関係に決まっている。
   契約が ±25% で動いたとき、射程の意味が変わるかは検証していない
