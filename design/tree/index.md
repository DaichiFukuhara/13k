## 1. これは何を決めるものか

js13kGames 2026 へ提出する作品を「**シードから技構成だけを生成した未知の敵を観察し、
移動・ジャンプ・ローリング・パリィ・交代を使い分けて崩す、1画面固定の2Dボスアクション**」
1本に確定する。

### 1.1 1戦の中身

プレイヤーが1戦のあいだ繰り返すループ。

1. 初見のボスが現れる。**姿から性格を推測する** — 武器シルエットの太さ（威力）、長さ（射程）、
   主色（最も危険度へ寄与した特性）、緑の輪郭の有無（防御能力）
2. 予備動作が始まる。**どこが危険か**（半透明のマーカー）と**いつ発生するか**（色の充填）が
   同時に出る
3. **選ぶ**。早めに範囲外へ出て安全を取るか、近距離を維持してロールやパリィで凌ぎ、
   反撃機会を取りに行くか
4. 攻撃後硬直へ攻撃を差し込む。**欲張ると次の予備動作に間に合わない**
5. スタミナの残りを見て、次を回避に使うか攻撃に使うかを決める
6. 技セットを理解するにつれ、被弾が減り、反撃が増える
7. 撃破後にシードと技構成が表示される

### 1.2 生成するもの / 生成しないもの

**この境界がこの企画の中心**である。生成するのはボスの「技構成」だけで、
戦闘が始まったあとの判定は一切生成しない。

| | 中身 |
| --- | --- |
| **生成する** | 攻撃技4〜5個（形状・数値・修飾子）／防御能力0〜1個／外見（体格・武器・主色・副色）／技の山札／最終ボスの第2形態変異1個 |
| **生成しない** | 当たり判定の形状／予備動作開始後の発生時刻／予備動作開始後の標的位置／攻撃後硬直／パリィ可能性／プレイヤーの基本性能／リトライ時の技セット |

つまりプレイヤーが対峙するのは**乱数ではなく、未知だが固定された相手**である。
死ぬたびに別の正解を引くのではなく、同じ相手を観察して学習する。

### 1.3 強さは予算で釣り合わせる

高威力・長射程・追尾・多段・短い予備動作といった強い特性には、**必ず長い予備動作か
長い攻撃後硬直を対応させる**。予算内で釣り合っていても成立しない組み合わせ
（高速 × 高威力 × 多段など）は、予算とは別に禁止する。

これにより「たまたま理不尽な敵が出る」ことを、運ではなく構造で防ぐ。

### 1.4 プレイヤーの道具立て

**操作するのは1人**。持っている手段は 移動 / ジャンプ / ローリング / パリィ の4つだけ。

**すべての生成攻撃は、最低2種類の有効な対処を持つ。**

- **反射神経を要求しない方法** — 早めの移動、距離を取る、ジャンプで越える
- **難しいが反撃しやすい方法** — 懐へロールする、刃をパリィする、近距離を維持する

上手い人だけが遊べるのではなく、**慎重に遊べば必ず抜けられて、上手く遊ぶと速く倒せる**。

### 1.5 資源はスタミナ1本

操作キャラは1人で、切り替えも控えも無い。**逃げ場は残機ではなく、スタミナ1本だけ**にする。

- ローリングとパリィがスタミナを食う
- 攻撃もスタミナを食う
- 消費後しばらく回復が止まる

だから「回避し続ける」も「殴り続ける」もできない。**強い行動ほど、次に何かを失う。**
何を切り詰めるかの判断が、1戦のあいだ途切れずに続く。

### 1.6 虹はルールであって装飾ではない

7色が攻撃特性の語彙になる。

| 色 | 示す傾向 |
| --- | --- |
| 赤 | 高威力 |
| 橙 | 長い攻撃判定・残留 |
| 黄 | 短い予備動作 |
| 緑 | 防御能力 |
| 青 | 長射程 |
| 藍 | 追尾 |
| 紫 | 多段・特殊変化 |

ボスの主色は「最も危険度へ寄与した特性」から決まる。**見た目が生成結果の関数になっている**
ので、色は飾りではなく読める情報になる。

ただし**色だけを見なければ遊べない設計にはしない**。攻撃範囲・時間・動きでも同じことを
示し、色は早く推測するための追加情報として置く。

> **推測から反応へ落ちる**」。虹を外すとゲームが別物になる、という形でテーマが

### 1.7 空間は1本の横軸

- 16:9 の1画面固定。スクロールしない
- 床は平面。落下死なし、足場なし
- **戦闘座標は横軸1本だけ**。プレイヤーとボスは同じ床の上にいる
- 奥行きを持たない。背景は演出専用で、当たり判定には使わない

Z軸の物理・奥行き用AI・複数レーン判定を持たない。

### 1.8 ランの構造（仮置き）

ボスを順に倒していくミニラン。1体ごとに全員回復し、難易度は**敵側の危険度予算だけ**で
上げる（プレイヤー側の成長で上げない）。負けたら同じ敵へ即再挑戦でき、そのとき
シード・技・数値は変わらない。

> 💬 **AI**: 体数と1体あたりの目標時間は 6 へ送った。ここで固定すると、
> 残り日数に応じて削る判断が下位でできなくなる。（2026-08-31）

### 1.9 「成立した」と言える2点

機能数でも生成できる組み合わせの多さでもなく、次の2点で判定する。

1. **生成された攻撃が、初見では緊張し、一度見れば理解できる**
2. **同じ敵への再挑戦で、乱数ではなくプレイヤーの学習によって勝率が上がる**

> 🧭 **AI**: 3人交代を落としたことで、旧3点目（交代が資源判断になっているか）が消えた。
> 測り方が無いまま残っていた項目なので、7 に立てていた未解決も同時に閉じた。
> 残る2点は 4 の「初見」「学習」へそのまま対応する。（2026-08-31）

   | 語 | 定義 |
   | --- | --- |
   | 技 | ボスが1回の予備動作から出す攻撃1つ。形状1つ＋数値＋修飾子で構成する |
   | 形状 | 当たり判定の作り方のテンプレート。技は必ずどれか1つを持つ |
   | 予備動作 | 攻撃判定が出る前の、危険範囲が表示されている時間 |
   | 攻撃判定 | 実際に当たっている時間 |
   | 攻撃後硬直 | 攻撃判定の終了後、ボスが次の行動を取れない時間。**プレイヤーの反撃時間そのもの** |
   | 危険度 | 技1つの強さの一次評価値。絶対的な強さではなく、生成してよい帯域を揃えるための値 |
   | 危険度予算 | ボス1体が持てる危険度の範囲 |
   | 山札 | 技の出る順序を決める仕組み。完全ランダムでも固定順でもない中間 |

### 他の切り方との比較

- **受け入れ条件6つをそのまま子にする案**: 却下。条件は課題ではなく**割り当て先**として使う
  （precedents 2026-08-29 で AIDE 本体側が同じ誤りをして取り下げている）
- **敵側 / プレイヤー側で切る案**（`foe` と `act`）: 両者を縛る「形状 × 回答手段の宣言」が
  seam になり、さらに同じ内容を `read` へも配るため2重になる。
  **人間の決定で操作キャラが1人になり、プレイヤー側が小さくなった**ので、`duel` へまとめた
- **機能で切る案**（生成器 / 戦闘 / 描画 / 音 / ビルド）: 子が5つになり予算ぎりぎりで、
  かつ生成器と戦闘の間に公平性の契約が通る。公平性は片方だけでは決められないので、
  切り口として悪い
- **2子案**（戦闘 / 提出）: `read` が `duel` の内部へ入ると、不変条件8（予告と判定の一致）を
  守る主体が消え、受け入れ条件「テーマ」の担当も居なくなる
- 子は3つ、深さ1。予算（深さ3・子数5）内
