## 1. これは何を決めるものか

js13kGames 2026 へ提出する作品を「**シードから技構成だけを生成した未知の敵を観察し、
移動・ジャンプ・ローリング・パリィ・交代を使い分けて崩す、1画面固定の2Dボスアクション**」
1本に確定する。

### 1.1 1戦の中身

プレイヤーが1戦のあいだ繰り返すループ。

1. 初見のボスが現れる。**姿から性格を推測する** — 武器シルエットの太さ（威力）、長さ（射程）、
   主色（最も危険度へ寄与した特性）、緑の輪郭の有無（防御能力）
2. 予備動作が始まる。**どこが危険か**（半透明のマーカー）と**いつ発生するか**（色の充填）が
   同時に出る
3. **選ぶ**。早めに範囲外へ出て安全を取るか、近距離を維持してロールやパリィで凌ぎ、
   反撃機会を取りに行くか
4. 攻撃後硬直へ攻撃を差し込む。**欲張ると次の予備動作に間に合わない**
5. HP かスタミナが苦しくなったキャラを奥へ下げ、別のキャラを前へ出す
6. 技セットを理解するにつれ、被弾が減り、反撃が増える
7. 撃破後にシードと技構成が表示される

### 1.2 生成するもの / 生成しないもの

**この境界がこの企画の中心**である。生成するのはボスの「技構成」だけで、
戦闘が始まったあとの判定は一切生成しない。

| | 中身 |
| --- | --- |
| **生成する** | 攻撃技4〜5個（形状・数値・修飾子）／防御能力0〜1個／外見（体格・武器・主色・副色）／技の山札／最終ボスの第2形態変異1個 |
| **生成しない** | 当たり判定の形状／予備動作開始後の発生時刻／予備動作開始後の標的位置／攻撃後硬直／パリィ可能性／プレイヤーの基本性能／リトライ時の技セット |

つまりプレイヤーが対峙するのは**乱数ではなく、未知だが固定された相手**である。
死ぬたびに別の正解を引くのではなく、同じ相手を観察して学習する。

### 1.3 強さは予算で釣り合わせる

高威力・長射程・追尾・多段・短い予備動作といった強い特性には、**必ず長い予備動作か
長い攻撃後硬直を対応させる**。予算内で釣り合っていても成立しない組み合わせ
（高速 × 高威力 × 多段など）は、予算とは別に禁止する。

これにより「たまたま理不尽な敵が出る」ことを、運ではなく構造で防ぐ。

### 1.4 プレイヤーの道具立て

移動 / ジャンプ / ローリング / パリィ / 交代。

**すべての生成攻撃は、最低2種類の有効な対処を持つ。**

- **反射神経を要求しない方法** — 早めの移動、距離を取る、ジャンプで越える
- **難しいが反撃しやすい方法** — 懐へロールする、刃をパリィする、近距離を維持する

上手い人だけが遊べるのではなく、**慎重に遊べば必ず抜けられて、上手く遊ぶと速く倒せる**。

### 1.5 交代は回避ボタンではない

3人を循環させる。ただし交代は**HP・スタミナ・反撃役を回す判断**であって、回避手段を
1つ増やすものではない。無敵を付けず、座標も変わらず、被弾硬直も消せない。

「敵の色を見て正解のキャラへ替えるだけの鍵合わせ」にはしない。誰か1人でなければ
回避できない攻撃を作らない。

### 1.6 虹はルールであって装飾ではない

7色が攻撃特性の語彙になる。

| 色 | 示す傾向 |
| --- | --- |
| 赤 | 高威力 |
| 橙 | 長い攻撃判定・残留 |
| 黄 | 短い予備動作 |
| 緑 | 防御能力 |
| 青 | 長射程 |
| 藍 | 追尾 |
| 紫 | 多段・特殊変化 |

ボスの主色は「最も危険度へ寄与した特性」から決まる。**見た目が生成結果の関数になっている**
ので、色は飾りではなく読める情報になる。

ただし**色だけを見なければ遊べない設計にはしない**。攻撃範囲・時間・動きでも同じことを
示し、色は早く推測するための追加情報として置く。

> 🧭 **AI**: 受け入れ条件「テーマ」の1文は、これを裏返して書ける。
> 「色を取り除くと、敵の性格を推測する手段が予備動作の観察だけになり、初見の判断が
> **推測から反応へ落ちる**」。虹を外すとゲームが別物になる、という形でテーマが
> ルールに接続している。（2026-08-31）

### 1.7 空間は1本の横軸

- 16:9 の1画面固定。スクロールしない
- 床は平面。落下死なし、足場なし
- **戦闘座標は手前の横軸1本だけ**
- 待機中の2人は同じ画面の奥に小さく描く。交代は奥と手前の入れ替えとして見せる
- 奥行きは演出専用で、当たり判定には使わない

2.5D の見た目を、Z軸の物理・奥行き用AI・複数レーン判定を持たずに得る。

### 1.8 ランの構造（仮置き）

ボスを順に倒していくミニラン。1体ごとに全員回復し、難易度は**敵側の危険度予算だけ**で
上げる（プレイヤー側の成長で上げない）。負けたら同じ敵へ即再挑戦でき、そのとき
シード・技・数値は変わらない。

> 💬 **AI**: 体数と1体あたりの目標時間は 6 へ送った。ここで固定すると、
> 残り日数に応じて削る判断が下位でできなくなる。（2026-08-31）

### 1.9 「成立した」と言える3点

機能数でも生成できる組み合わせの多さでもなく、次の3点で判定する。

1. **生成された攻撃が、初見では緊張し、一度見れば理解できる**
2. **同じ敵への再挑戦で、乱数ではなくプレイヤーの学習によって勝率が上がる**
3. **交代が回避ボタンの追加ではなく、HP・スタミナ・反撃役を回す判断になっている**

> 🧭 **AI**: この3点は 4 の受け入れ条件「初見」「学習」へ対応させた。
> 3 番目だけ受け入れ条件に直接の対応が無い（測り方が決まっていない）ので、
> 7 に未解決として立てた。（2026-08-31）

## 5. 変えてはいけない前提

**A. 大会ルール（外から与えられ、動かせない）**

1. 提出 ZIP は 13,312 bytes 以下。最上位に `index.html` を置く
2. 外部リソースに依存しない（CDN・外部画像・外部フォント・外部API を使わない）
3. 締切は 2026-09-13 20:00 JST
4. テーマ「Unicorns and Rainbows」は採点対象である
5. 遊べる ZIP と、ビルド可能な読めるソースの**両方**を提出する

**B. 根自身の不変条件（継承ではなく著述）**

6. **提出は1本だけ**。並存させない
7. **生成するのは敵の技構成であって、戦闘中の当たり判定ではない**（1.2）。
   攻撃開始後に、発生時刻・範囲・形・標的位置を乱数で変えない
8. **予告した危険範囲と、実際の当たり判定は、同一の定義から作る**。
   表示用の形を別に持たない
9. **同じシードは同じ敵を再現する**。負けた直後に別の敵へ変わらない
10. **すべての生成攻撃は、反射神経に依存しない回答を最低1つ持つ**（1.4）。
    確率で回避が決まる要素を作らない
11. **交代に無敵を与えない**（1.5）。特定キャラでなければ回避できない攻撃を作らない
12. **色だけに依存させない**（1.6）。範囲・時間・動きでも同じ情報を示す
13. 画像ファイル・音声ファイル・外部ライブラリを持たない（描画と音は実行時に生成する）

> 🧭 **AI**: 7〜12 は `SOULS_ACTION_DESIGN.md` から採ったが、あれは**企画案であって決定ではない**
> ので、根の不変条件として採用し直す形で書いた。この6つは「このゲームがこのゲームである」
> ことの定義で、子が選び直すと別のゲームになる。数値・技の種類・キャラ性能は含めない（6 へ）。
