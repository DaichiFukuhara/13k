## 前検査を3回回した。まだ通っていない

| 回 | 対象 | 結果 |
| --- | --- | --- |
| 1 | `split-1`（**承認済みだった**もの） | 重大5・軽微2 / **修正のうえ再提案** |
| 2 | `split-3`（案 B） | 重大8・軽微3 / **判定不能** |
| 3 | `split-4`（案 B′） | 重大8・軽微4 / **判定不能** |

3回目の追跡表では、重大8と軽微2・3が**解消**、重大2〜7が**部分的に解消**。改善はしているが、
`decision-3` が pending であるかぎり規定上の正式判定は出ない（`precheck.md` 確認項目1）。

**提案側（Claude）の誤りが3件あった**（すべて `precedents.md` 2026-09-01 に記録）。

1. **「親へ移す」を「結合が消える」と取り違えた。**`split-3` は「根は全子の状態を直接読める」を
   論拠に受け入れ条件3つを根へ移したが、`harness/README.md`「見てよいのは、自分と祖先だけ」により
   **根の閉包に子は含まれない**
2. **結合を別名にして指標の外へ置いた。**`split-4` は報告経路6端点を「兄弟間 seam ではない」として
   2端点で評価した。Codex 曰く「**自己申告しても判定は改善しない**」。8端点へ訂正済み
3. **人間の判断を、技術的に正しい理由で読み替えた。**「`seam_inbox` 経由」という判断に対し、
   提案側は `## reports` を新設した。理由は正しくても**読み替えてよいことにはならない**

## 人間の判断が要る

**済んだもの**

- ~~`decision-2` の決定の承認~~ → 2026-09-01 承認済み（本文1から「交代」を削除）
- ~~A / B の選択~~ → 2026-09-01、**B を選択**

- ~~実装基盤~~ → 2026-09-01、**まだ決めない**（`deferred`。再開条件を
  「最初の**深さ2**の分割承認まで」へ具体化。深さ1は基盤を知らずに進められるため）

**未決（`split-5` を書くための前提）**

1. **`reports` か `seam_inbox` か。**提案側が判断を読み替えた件の差し戻し（Codex 3回目・重大4）
2. **「期限」の扱い。**根に割り当てたままだが、ビルド・提出を行う `implement` から根への
   完了報告が無く、**根は「提出が完了した」を判定できない**（同・重大5）
3. **`implement` が締切に間に合わない場合の代替。**`deferred` の再開条件に期限が無い。
   残り12日（2026-09-13 締切）で `implement` が作られなければ、
   「提出可能」は誰にも判定されないまま締切を迎える（同・重大6）
4. 1〜3 が決まってから **`decision-3` の承認 → `split-5` の起草 → Codex の4回目の前検査 →
   分割の承認 → 振り分けの転記**

**現時点で有効な分割提案は無い**（`split-1` superseded / `split-2` withdrawn /
`split-3` rejected / `split-4` pending）。

## 子ノードの進め方

**1チャット = 1ノード。子は cold start で開く。**会話の続きではなく、ファイルだけで始める。

```
design/harness/README.md に従って design/tree/duel を進めてください。
閉包（自ノードと祖先チェーンの index.md）を先に読んでください。
```

`duel` の部分を `read` / `ship` に替えれば、そのまま各ノードの入口になる。
**兄弟の index.md は読まない。**兄弟との接続は各ノードの `uses_seams` と、
親の分割提案にすべて書かれている。

これで始められないなら、原因はチャットではなく**ツリーに書かれていない情報**にある。

> ⛔ **ただし現在は使えない。**上の「人間の判断が要る」4件が済むまで、
> 子の `## 親からの振り分け` は失効している。
