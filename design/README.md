### 提案側が繰り返している誤りの型

`precedents.md` 2026-09-01 / 09-04 に記録。**同じ型が深さを変えて再発している。**

1. **「親へ移す」を「結合が消える」と取り違える。**`split-3` は受け入れ条件を根へ移して
   結合が消えたとしたが、根の閉包に子は含まれない。
   **`duel-split-1` でも再発**した — プレイヤーの当たり判定サイズを親へ移して
   `fight → gen` の逆向きを消したつもりが、ジャンプの高さ・滞空・ロールの無敵
   （「回答手段の宣言」を検証するのに要る値）は `fight` に残っていた
2. **結合を別名にして指標の外へ置く。**`split-4` は報告経路6端点を
   「兄弟間 seam ではない」として2端点で評価した。Codex 曰く
   「**自己申告しても判定は改善しない**」
3. **人間の判断を、技術的に正しい理由で読み替える。**理由が正しくても読み替えてよいことにはならない
4. **担当がいるように見せかけた割り当て。**子名は付いているが、
   判定する入力・実行者・統合責任が無い（`split-1` 重大4 →
   `duel-split-1` 重大6・7 で再発）

### 前検査が直したのはハーネスだけではない

ゲーム本体も直っている。根の 1.3（公平性の保証）は**3回書き直された**。

| 回 | 指摘 | 直した内容 |
| --- | --- | --- |
| 2 | 「短い予備動作の代償が長い予備動作」という論理矛盾 | 特性軸と代償軸を分離 |
| 3 | 「射程外に立てば安全」が追尾・多段・接近後攻撃で破れる | **危険包絡**を定義して生成時に検査する形へ |
| 3 | 安全席は存在するがプレイヤーが包絡内から始まる | **選択時条件**（黄はプレイヤーが既に安全席に居る時だけ出せる） |

3 は結果としてメカニクスになった。プレイヤーから見ると
**「安全な位置に居れば速い技が来る、居なければ来ない」** — 位置取りが意味を持つ。

## 子ノードの進め方

**1チャット = 1ノード。子は cold start で開く。**会話の続きではなく、ファイルだけで始める。

```
design/harness/README.md に従って design/tree/duel を進めてください。
閉包（自ノードと祖先チェーンの index.md）を先に読んでください。
```

`duel` の部分を `read` に替えれば、そのまま各ノードの入口になる。
**兄弟の index.md は読まない。**兄弟との接続は各ノードの `uses_seams` と、
親の分割提案にすべて書かれている。

これで始められないなら、原因はチャットではなく**ツリーに書かれていない情報**にある。
